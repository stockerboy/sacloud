# 파이프라인 관측 도구 (2026-09-08 · P0)

> 사장님: «사이트를 보고 「왜 기록이 안 들어왔지?」 할 때 30분 조사하지 않고
> ★어느 단계가 문제인지 1~2분 안에★ 알 수 있게 만들어라»

전부 **읽기 전용**이다. 운영 DB 에 한 줄도 쓰지 않는다.

```bash
node scripts/pipeline/diag.mjs     # ★제일 먼저 이걸 본다★ — 5단계 중 어디서 멈췄는지
node scripts/pipeline/health.mjs   # 큐 포함률·각 단계 최신 시각·임대
node scripts/pipeline/e2e.mjs      # 경기 → Match → 배틀로그 → 라인업 실제 지연
node scripts/pipeline/latent.mjs   # 시간이 지나면 터지는 조건 훑기
node scripts/pipeline/lap.mjs      # 회차 한 줄 기록 (lap.log 에 덧붙인다)
```

## 왜 ①과 ②를 갈라 놓았나

`diag.mjs` 는 **「물어봤나」(①)** 와 **「받았나」(②)** 를 따로 본다.

2026-09-08 에 수집이 **8시간** 멈췄는데 아무도 몰랐다.
로그에는 「목록 요청 150회」만 찍혀서 정상으로 보였기 때문이다.
실제로는 **죽은 클랜 150곳**에 물어보고 있었다.

- ① 최신 + ② 낡음 → **새 경기가 없는 것** (밤낮 차이 · 정상)
- ① 낡음 → **수집기가 죽은 것** (장애)

이 구분이 없으면 「경기가 없는 시간대」와 「고장」을 못 가린다.
