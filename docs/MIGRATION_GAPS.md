# MIGRATION_GAPS.md — 3rd.supply 데이터 이전 가능성 조사

3rd.supply의 누적 기록을 SACLOUD로 이전하기 위해, **실제로 접근 가능한 범위**를 조사한 결과다.
추측이 아니라 2026-08-20에 직접 요청해서 받은 응답을 근거로 한다.

관련 문서: `docs/MIGRATION_PLAN.md`(파이프라인 설계) · `docs/MIGRATION_REPORT.md`(실행 결과)

---

## 0. 결론 요약

| 데이터 출처 | 접근 상태 | 판정 |
|---|---|---|
| `api-v2.3rd.supply` (원본 API) | **403 Forbidden** (AWS ELB, 모든 외부 요청) | 이전 불가 |
| `3rd.supply` (웹 페이지, SSR) | **AWS WAF CAPTCHA 챌린지** (`x-amzn-waf-action: captcha`) | 자동 수집 불가 |
| `open.api.nexon.com/suddenattack` (넥슨 공식 Open API) | **정상 (API Key 필요)** | **이전 가능 — 단, 경기 원천 기록에 한함** |

**핵심 판단**

1. 3rd.supply는 자동화 수집을 막는 **봇 차단(WAF CAPTCHA)** 을 걸어두었다.
   이것을 우회하는 것은 사업자가 설정한 접근 통제를 무력화하는 행위이므로 **하지 않는다.**
   (`CLAUDE.md` 및 작업 지침의 "API rate limit 우회 금지 / 비공개 데이터 무단 접근 금지"에 해당)
2. 경기 **원천 기록**(킬·데스·어시스트·무기·딜량·헤드샷·승패·맵·시각)의 1차 출처는
   3rd.supply가 아니라 **넥슨 병영수첩**이다. 3rd.supply도 거기서 수집한다.
   따라서 SACLOUD는 **넥슨 Open API에서 직접 수집**하면 같은 원천 기록을 합법적으로 확보할 수 있다.
3. 그러나 **3rd.supply가 자체 계산한 값**(래더·`rating_update`·랭킹·리그/시즌/부리그 구성·배치고사)은
   넥슨에 존재하지 않는 3rd.supply 고유 산출물이다. **운영자 협조 없이는 확보할 방법이 없다.**

## 1. 실측 근거

### 1-1. `api-v2.3rd.supply` — 외부 요청 전면 차단

```
GET https://api-v2.3rd.supply/infos
→ HTTP/1.1 403 Forbidden
  Server: awselb/2.0
  (응답시간 0.07s — 애플리케이션이 아니라 로드밸런서 단에서 거부)
```

`/leagues`, `/remote_configs`, `/robots.txt` 전부 동일하게 403.
브라우저 컨텍스트가 아닌 요청은 전부 차단된다.

### 1-2. `3rd.supply` 웹 오리진 — WAF CAPTCHA

```
GET https://3rd.supply/league/supply/rank/clan/1
→ HTTP/1.1 405 Not Allowed
  Server: CloudFront
  x-amzn-waf-action: captcha
  Content-Type: text/html  ("Human Verification" 페이지)
```

AWS WAF의 **CAPTCHA 액션**이 걸려 있다. 자동화된 요청은 사람 확인 페이지로 돌려보낸다.

### 1-3. `robots.txt` 와 이용약관 — 참고

```
https://3rd.supply/robots.txt
  User-agent: *
  Allow: /
  Sitemap: https://3rd.supply/sitemap.xml
```

- robots.txt 자체는 크롤링을 허용한다.
- 이용약관에는 자동 수집·크롤링을 **명시적으로 금지하는 조항이 없다.**
- 다만 약관에 **"서비스에 대한 저작권 및 지적재산권은 서플라이에 귀속"** 취지의 조항이 있고,
  금지행위에 "제3자의 지적재산권 침해"가 포함되어 있다.
- **robots.txt가 허용이어도 실제 서버는 WAF로 자동 접근을 차단한다.**
  선언과 실제 통제가 다를 때는 **실제 통제를 따른다.**

### 1-4. `open.api.nexon.com` — 넥슨 공식 Open API (서든어택 지원 확인)

```
GET https://open.api.nexon.com/suddenattack/v1/id
→ {"error":{"name":"OPENAPI00004","message":"Please input valid parameter"}}

GET .../suddenattack/v1/id  (x-nxopen-api-key: <잘못된 키>)
→ {"error":{"name":"OPENAPI00005","message":"The apikey is not valid."}}
```

- 서든어택은 넥슨 Open API에서 **정식 지원**된다 (게임 id 41).
- 공개된 카테고리: **계정 정보 조회 / 매치 정보 조회 / 메타데이터 정보 조회**
- 인증: 요청 헤더 `x-nxopen-api-key` **필수**
- 이용 조건에 명시: 가져간 데이터는 **최소 30일마다 갱신**해야 한다
  → SACLOUD의 수집 주기 설계에 반영해야 하는 제약이다.

| # | 데이터 종류 | 등급 | 접근 불가능한 이유 | SACLOUD에 미치는 영향 | 대체 방법 |
|---|---|---|---|---|---|
| 1 | 경기(match) 목록 | A | — | 없음 | 넥슨 매치 정보 조회 |
| 2 | 경기별 참가자 | A | — | 없음 | 넥슨 매치 상세 |
| 3 | kill / death / assist | A | — | 없음 | 넥슨 매치 상세 |
| 4 | weapon (라이플/스나이퍼) | A | — | 없음 | 넥슨 매치 상세 |

| 7 | 맵 / 대전인원 / 경기시각 | A | — | 없음 | 넥슨 매치 상세 |
| 8 | 플레이어(닉네임·식별자) | A | — | 없음 | 넥슨 계정 정보 조회 |

| 13 | **래더(rating) 현재값** | **B** | 3rd.supply 자체 계산값 | 기존 래더 승계 불가 | 운영자 협조 / 신규 산정 |

| 16 | **배치고사(placement) 상태** | **B** | 3rd.supply 운영 개념 | 배치 이력 유실 | 신규 배치 |

| 22 | 클랜마크 이미지 | **C** | 넥슨/클랜의 자산 | 마크 미표시 | 넥슨 API가 제공하면 그쪽 사용 |
| 23 | 리그 소개/규정 HTML | **C** | 운영자 저작물 | 리그 소개 공란 | 운영자 협조 |

## 3. 이 조사로 확정된 제약

1. **3rd.supply에서의 직접 대량 수집은 하지 않는다.**
   WAF CAPTCHA는 명시적 봇 차단이다. 브라우저 자동화로 우회하는 것도 같은 통제를 무력화하는 것이므로 하지 않는다.
2. **경기 원천 기록은 넥슨 Open API를 1차 출처로 삼는다.**
   3rd.supply를 경유하지 않으므로 데이터베이스제작자 권리 문제도 발생하지 않는다.
3. **3rd.supply 고유 산출물(등급 B)은 운영자 협조 없이는 확보 불가하다.**
   요구사항의 "시즌 번호 연속성", "과거 시즌 최종 기록", "historical `rating_update` 원본 보존"은
   **운영자로부터 데이터를 제공받는 경우에만** 충족 가능하다.
4. **게시판·계정(등급 C)은 이전하지 않는다.** 제3자 저작물·개인정보다.

## 4. 사용자 결정이 필요한 사항

| # | 결정 사항 | 필요한 이유 |
|---|---|---|
| D1 | **넥슨 Open API Key 발급** | 경기 원천 기록 수집의 유일한 합법 경로. 키 없이는 한 건도 못 가져온다 |
| D2 | **3rd.supply 운영자와의 데이터 제공 협의 여부** | 래더·시즌·랭킹·`rating_update` 등 등급 B 데이터는 이 경로 외에 방법이 없다 |
| D3 | D2가 불가능할 경우의 대체 정책 | 예: 시즌 번호를 SACLOUD 기준 Season 1부터 시작 / 래더는 전원 초기값부터 재시작 |
