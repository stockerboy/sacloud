## 5. ★가장 중요한 발견 — 병영수첩 수집 길이 뚫렸다★

### 5-1. 무엇이 밝혀졌나

앞 세션들은 「병영수첩은 막혔다」로 결론짓고 멈춰 있었다. **절반만 맞았다.**

```
Node(서버)에서   GET /  ·  매치목록  ·  배틀로그      전부 403      ← 오늘 재측정. 사실이다
진짜 브라우저    같은 셋                              전부 200      ← 오늘 처음 확인
```

**진짜 브라우저에서는 보안 검사조차 안 뜬다.** 그냥 열린다.
헤드리스로 시험했던 앞 세션 결론(「헤드리스도 403」)은 헤드리스에 한해 맞았다.

  → 200 · 63,429 바이트
  → battleLog[] : 킬/데스 이벤트 · 좌표(death_x/y, kill_x/y) · 라운드 · event_time

그리고 **로컬 작업 트리에서는 셋 다 안 잡힌다** — 파일이 다 있으니까.

> pnpm --filter @sacloud/web build

  프로젝트 id 는 `.vercel/project.json`. **API 호출도 끊기니 재시도를 감싸라** (5~8회면 통과).

### 6-3. 운영 마이그레이션은 **5432 포트**로 (D-261)

### 6-4. `Promise.all` 이 운영에서 죽는다

운영 접속 문자열이 `connection_limit=1` 이라(D-239) 동시에 여러 질의를 걸면
**병렬이 아니라 10초 풀 타임아웃**이다. 순차로 바꾼다.

### 6-5. Bash heredoc 이 백슬래시를 먹는다

`\n` 을 heredoc 으로 넣으면 **진짜 줄바꿈**이 되어 코드가 조용히 깨진다.
오늘 실제로 당했다. 파이썬/노드 코드를 heredoc 으로 넣을 때는 백슬래시를 `chr(92)` 로 만들거나
Write 도구로 파일을 쓴 뒤 실행한다.

### 6-6. 아티팩트는 **자기 사본을 들고 저장한다**

점검표 아티팩트(`552435cd-…`)는 `<script id="sh-data">` 에 자기 자신의 base64 를 들고 있고,
사용자가 「저장」을 누르면 **그 사본으로 되돌아간다.**
본문만 고쳐 올리면 사용자 저장 한 번에 내 수정이 통째로 날아간다. **오늘 실제로 그렇게 날아갔다.**
빌드 스크립트가 사본까지 다시 굽고 자기검사를 하도록 고쳤다
(스크래치패드 `build.py` — 세션과 함께 사라지므로 필요하면 다시 만든다).

## 11. 새 세션에게 — 이 프로젝트에서 가장 중요한 세 가지

1. **없는 값을 지어내지 마라.** 0 으로 채우지 말고 `null` 로 두고 화면이 「알수없음」·「기록 없음」을

2. **「됐다」를 로그로 판정하지 마라.** 숫자를 세거나 화면을 찍어라.
   사용자가 반복해서 요구한 것이 이것이다 — *"거짓말 하지 마라"*.
3. **옛 방식을 지우지 마라** (CLAUDE.md 10-4). 새 것을 기본으로 하되 옛 것은 남기고,
   문서는 「그때는 이랬고 지금은 이렇다」로 이어 적는다.
