## 2. 점수표 — 사장님이 직접 주신 곡선

> 「상대스나를 선짤했다? 이러면 1점 / 거기서 1킬 더? 2점 / 거기서 또 1킬 더? 4점 /
> 거기서 1킬 더? 6점 / 올킬? 10점 / 이런느낌임」

| 무엇 | 점수 |
|---|---|
| 상대 스나를 **라운드 첫 킬**로 잡음 | 1 |
| + 1킬 더 (총 2킬) | 2 |
| + 1킬 더 (총 3킬) | 4 |
| + 1킬 더 (총 4킬) | 6 |
| **올킬 (5킬)** | **10** |
| 선짤 없이 킬만 한 라운드 | 그 절반 (0.5 / 2 / 3 / 5 / 8) |
| 세이브 (혼자 남아 이김) | +3 |
| 소수싸움에서 살아남아 1킬 이상 | +2 · 그 라운드까지 따면 +2 더 |

오름폭이 **+1 → +2 → +2 → +4** 로 뒤로 갈수록 가팔라진다.
올킬이 선짤의 열 배 — 「혼자 판을 끝냈다」를 확실히 띄우는 모양이다.

라플은 시작점만 「라운드 첫 킬」로 바꾼다 — 스나는 **상대 스나를** 잡아야 선짤이지만
라플은 누구를 잡든 판을 연 것이다.

### 여기까지 오는 데 세 번 틀렸다

1. 처음엔 **「첫 킬 뒤 10초 잠잠했나」** 로 쟀다 (사장님 원안)

2. 대조군을 「다음 킬이 빨리 났다」로 뭉쳤는데 그중엔 **우리가 또 잡은 것**도 있었다.
   비교가 성립을 안 했다.
3. 셋으로 가르니(잠잠 / 굳힘 / 깨짐) 비로소 보였다 — **시간이 아니라 「다음 한 수」** 였다.

## 10. 개인 6축 — 어떻게 담았나

**키는 여섯이고 무기별로 다른 값이 들어간다.** 계약의 `TRAIT_AXIS_LABEL` 이 이미
`{sniper, rifle}` 쌍이라 그 틀을 그대로 썼다.

| 키 | 스나 | 라플 | 셈 |
|---|---|---|---|
| `save` | 세이브 | 세이브 | 혼자 남아 이긴 비율 (공통) |
| `duel` | 스나싸움 | 화력 | 같은 무기끼리 붙어 이긴 비율 |
| `chance` | 기회창출 | 기회차단 | 스나 = 그 라운드 첫 킬 · 라플 = 맞고 시작한 라운드에서 되받음 |
| `safe` | 안전함 | 크랙 | 스나 = 끝까지 산 비율 · 라플 = 116칸에서 25초 안 첫 킬 |
| `gap` | 스나차이 | 라플차이 | 그 선수 팀의 무기 쪽이 상대보다 앞선 판 비율 |
| `outnumbered` | 소수싸움 | 소수싸움 | 수가 밀린 라운드를 이긴 비율 (공통) |

**DB 칸은 갈지 않았다** — `chance→carry*` · `safe→opening*` · `gap→burst*`.
칸을 갈면 마이그레이션이 커지고, 어느 판인지는 `formulaVersion` 이 가른다.

### 재집계 결과 (선수 3,550명)

| | 라플 1,265명 | 스나 217명 |
|---|---|---|
| 기회창출 / 기회차단 | 9.4% | **20.4%** |
| 안전함 / 크랙 | 21.7% | **30.2%** |
| 스나차이 / 라플차이 | 49.6% | 51.2% |

숫자가 뜻과 맞는다 — 스나가 첫 킬을 두 배 자주 내고 더 자주 살아남는다.

### 부호 뒤집기가 없어졌다

전날 「게임템포」만 작을수록 좋아서 `axisScoresOf` 가 부호를 뒤집고 있었다.
「안전함」은 클수록 좋으므로 **여섯이 전부 「클수록 좋다」** 가 됐다. 뒤집기를 지웠다
(`HEX_LOWER_IS_BETTER` 는 빈 배열로 남긴다 — 그런 축이 다시 생기면 거기 넣으면 된다).

### 여기서도 두 번 틀렸다

1. **「앞선 판」 질의가 타임아웃** — `LeagueClan` 을 OR 로 이었다.
   `side` 가 어느 쪽인지 바로 말해 주므로 `Match` 의 `red/blueLeagueClanId` 로 곧장 이으면 된다.
2. **137% 가 나왔다** — `COUNT(*)` 로 셌는데 한 경기에 같은 선수 줄이 여럿이면 두 번 세어졌다.
   분모는 `DISTINCT` 였다. `COUNT(DISTINCT matchId)` 로 맞추고 값에도 상한을 뒀다.
