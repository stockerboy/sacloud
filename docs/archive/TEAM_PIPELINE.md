# 팀 운영 규칙 — 사장 · 총괄팀 · 제작팀

> 2026-09-02 사장님 지시로 만든 문서.
>
> > *"세션 하나 더 열어서 걔는 제작팀으로 일할거야 나-총괄팀-제작팀 이런 파이프라인이야"*
>
> **이 문서는 「누가 무엇을 하고, 무엇을 하면 안 되는가」를 정한다.**
> 기술 상세는 `docs/HANDOFF_2026-09-02_EVENING.md`, 판 전체는 `docs/PROJECT_BRIEF.md`.

---

## 1. 파이프라인

```
        사장님
          │  결정 · 우선순위 · 최종 승인
          ▼
      ┌────────────┐
      │  총괄팀     │  무엇을 · 왜 · 어떤 순서로
      │ (매니저)    │  받은 것을 쪼개고 · 검수하고 · 사장님께 보고
      └────────────┘
          │  작업 지시서 (아래 4장 형식)
          ▼
      ┌────────────┐
      │  제작팀     │  어떻게 · 실제로 코드를 고친다
      │ (구현)      │  근거를 붙여 총괄팀에 되돌린다
      └────────────┘
```

**보고는 거꾸로 올라간다.** 제작팀 → 총괄팀 → 사장님.
제작팀이 사장님께 직접 「됐습니다」를 말하지 않는다 — **총괄팀이 검수한 뒤 보고한다.**

## 2. 역할

### 2-1. 사장님

- 무엇을 만들지 정한다. 우선순위를 정한다.
- **결정 대기 항목**(`PROJECT_BRIEF.md` 6장)에 답한다.
- 점검표 아티팩트에 피드백을 적는다.

### 2-2. 총괄팀 (매니저 세션)

**하는 일**

```
· 사장님 지시를 받아 **작업 지시서**로 쪼갠다 (4장 형식)
· 순서를 정한다 — 선행 작업이 안 끝났는데 뒤를 시키지 않는다
· 제작팀이 올린 결과를 **검수**한다 (5장 기준)
· 사장님께 보고한다. 안 된 것은 안 됐다고 그대로 올린다
· 문서를 최신으로 유지한다 (DECISIONS · TASK_LEDGER · HANDOFF)
· D- 번호를 배정한다 (충돌 방지 — 오늘까지 세 번 났다)
```

**하지 않는 일**

```
· 코드를 직접 고치지 않는다 (급한 한 줄이라도 제작팀을 거친다)
  → 이유: 같은 파일을 둘이 만지면 오늘처럼 빌드가 깨진다
· 근거 없이 「됐다」고 사장님께 보고하지 않는다
```

### 2-3. 제작팀 (구현 세션)

**하는 일**

```
· 지시서 한 건을 끝까지 처리한다
· 끝냈으면 **근거**를 붙여 총괄팀에 올린다 (5장)
· 하다가 지시가 틀렸다는 걸 알면 **멈추고 총괄팀에 알린다** (혼자 바꾸지 않는다)
```

**하지 않는 일**

```
· 지시 범위 밖을 손대지 않는다. 좋은 아이디어는 총괄팀에 올린다
· 사장님께 직접 보고하지 않는다 (사장님이 직접 물으면 그때는 답한다)
· 다른 팀이 담당한 파일을 만지지 않는다 (3장)
```

## 3. ★파일 소유 구획 — 오늘 빌드가 3번 깨진 이유★

### 3-1. 무슨 일이 있었나

두 세션이 같은 저장소를 동시에 고쳤다.
`packages/ui/src/index.ts` 는 **모든 컴포넌트가 지나가는 길목**이다.
한쪽이 만들던 컴포넌트의 **내보내기 줄만** 다른 쪽 커밋에 딸려 갔고,
정작 **그 파일은 커밋 안 돼 있었다.**

```
로컬에서는 파일이 다 있으니 tsc 도 테스트도 통과한다
원격 빌드에서만 터진다 — 세 번을 하나씩 찾아 고쳤다
```

### 3-2. 규칙

```
① 한 번에 **한 팀만** 코드를 고친다
   총괄팀이 「지금은 제작팀 차례」를 명시한다. 겹치면 반드시 사고가 난다

② 길목 파일은 **작업 시작 전에 선언**한다
   packages/ui/src/index.ts        모든 컴포넌트의 관문
   packages/contract/src/index.ts  모든 계약의 관문
   packages/db/prisma/schema.prisma DB 스키마
   docs/DECISIONS.md               모두가 이어 적는 문서
   pnpm-lock.yaml                  의존성

③ 커밋 전 **깨끗한 worktree 빌드**를 돌린다 (5장)
   이것만이 「내 로컬에는 있는데 커밋엔 없는 파일」을 잡는다

④ 커밋은 **자기 파일만** 고른다. `git add -A` 를 쓰지 않는다
   그리고 자기 파일이 *가리키는* 것이 커밋됐는지까지 본다
```

## 4. 작업 지시서 형식 (총괄팀 → 제작팀)

```markdown
## [지시 #12] IPL 경기목록 페이징 해결

### 왜
IPL 킬데스가 6.3%뿐이다. 전수 수집을 하려면 경기 목록을 다 받아야 하는데
GetClanMatchList 가 한 번에 20건만 준다. 이걸 못 풀면 나머지가 전부 막힌다.

### 무엇을
`POST /api/ClanHome/GetClanMatchList/` 의 페이지 넘기는 법을 찾는다.

### 이미 시도해서 실패한 것 (다시 하지 마라)
page · page_no · offset · start · last_match_key · match_key  → 전부 같은 20건

### 끝난 것으로 치는 기준
한 클랜의 7/1 이후 경기를 **빠짐없이** 받아 개수를 세어 보인다.
그 클랜의 `Match` 표 건수와 대조해 일치하거나, 차이를 설명할 수 있어야 한다.

### 만지는 파일
scripts/battlelog-collect-snippet.js · docs/IPL_SPEC.md
(길목 파일 없음)

### 만지면 안 되는 것
운영 DB 쓰기 · packages/ui/**
```

**지시서에 반드시 들어가는 것**

```
왜 (이게 없으면 제작팀이 잘못된 것을 최적화한다)
끝난 것으로 치는 기준  ← ★가장 중요★. 「됐다」의 정의를 미리 못 박는다
이미 실패한 시도
만지는 파일 / 만지면 안 되는 것
```

## 5. 검수 기준 (제작팀 → 총괄팀)

제작팀은 아래를 **전부** 붙여서 올린다. 하나라도 없으면 총괄팀은 되돌린다.

```
□ typecheck 통과      pnpm typecheck  (또는 해당 패키지)
□ 테스트 통과         pnpm vitest run --no-file-parallelism
                      ★순차로★ 돌린다. 병렬이면 DB 테스트가 5초 타임아웃난다
□ 깨끗한 트리 빌드    git worktree add --detach <임시> HEAD
                      pnpm install --frozen-lockfile && pnpm --filter @sacloud/web build
                      ← 로컬 작업 트리 빌드는 이 사고를 못 잡는다
□ 화면이 바뀌었으면 **찍은 그림**
                      로컬 dev 가 안 뜨므로(6장) 배포본을 찍는다
                      scripts/render-audit/shoot.mjs
□ 데이터를 건드렸으면 **숫자 대조**
                      «로그에 성공이라 찍혔다» 는 근거가 아니다. 세어서 보인다
□ 실패한 것은 실패했다고 적는다
                      남의 세션 때문에 실패한 것이면 그것도 적는다
```

### 총괄팀이 되돌리는 경우

```
· 근거 없이 「됐습니다」
· 없는 값을 0 으로 채웠다 (null 로 두고 화면이 「알수없음」을 적어야 한다)
· 옛 방식을 지웠다 (CLAUDE.md 10-4 — 남기고 새 것을 기본으로 한다)
· 지시 범위 밖을 손댔다
· 리그별로 칸을 감추는 분기를 새로 만들었다 (CLAUDE.md 9장)
```

## 8. 보고 주기

```
제작팀 → 총괄팀    지시서 한 건이 끝날 때마다. 그리고 막히면 즉시
총괄팀 → 사장님    ① 지시를 받았을 때 «무엇을 어떤 순서로» 를 한 번
                   ② 묶음이 끝났을 때 결과 + 근거
                   ③ 결정이 필요할 때 (선택지와 각각의 대가를 붙여서)
```

**보고 형식** — 사장님은 긴 글을 싫어한다. 휴대폰으로 본다.

```
코드 블록 하나에 평문으로. 표 대신 줄맞춤.
「됐다 / 안 됐다 / 막혔다」를 먼저, 근거를 뒤에.
```

### `@@` 규칙

사장님 메시지가 `@@` 로 시작하면 **1분 안에** 답한다.
하던 일을 멈추지 않고, 아는 것만으로, 두 줄 이내로.
모르면 모른다고 쓴다 — **끝났다고 지어내지 않는다.**
