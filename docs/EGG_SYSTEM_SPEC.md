## 0. 한 줄 요약

```
모든 클랜과 선수의 기록을 **알**로 덮어 둔다.
알을 깨야 기록이 보인다. 알을 깨는 방법은 **가입하고 본인 인증하는 것**이다.
```

궁금하게 만들어 가입을 유도하는 장치다. **기록을 지우는 것이 아니라 가려 두는 것**이다.

## 2. 알이 가리는 것 / 안 가리는 것

**핵심 원칙: 판수와 경기 상세기록은 가리지 않는다.** 있다는 것은 보여 주고, 얼마나 잘하는지를 가린다.

| | 알이 있을 때(안 깨짐) | 알이 깨졌을 때 |
|---|---|---|
| 판수 | **보인다** | 보인다 |
| 경기 상세기록 | **보인다** | 보인다 |
| 승률 | 가린다 | 보인다 |
| N승 N패 | 가린다 | 보인다 |
| 6각형 (개인·클랜) | 가린다 | 보인다 |
| 킬뎃 | **DPL 은 가린다** · IPL 은 해당 없음(원래 없다) | 보인다 |
| 그 밖에 우리가 만든 지표 | 가린다 | 보인다 |

가린 자리에는 **"알이 깨지면 기록을 볼 수 있습니다"** 를 띄운다. 빈칸으로 두지 않는다 —
비어 있으면 없는 줄 알지만, 문구가 있으면 궁금해진다.

> `[미확인]` "우리가 만든 또 다른 추가적 기능들" 의 정확한 목록. 지금 있는 것 기준으로는
> 플레이스타일 바 · 포지션 · 라운드 지표 · 오늘 기록이 후보다. 사용자 확인이 필요하다.

## 3. 알을 깨는 법

```
개인 알   본인이 가입하고 **본인 인증**에 성공하면 자기 알이 깨진다
클랜 알   그 클랜원의 **30% 이상**이 각자 알을 깨면 클랜 알이 깨진다
          ─ 또는 ─
          **클랜마스터**가 본인 인증에 성공하면 **혼자서도** 클랜 알을 깬다
```

깨진 클랜은 **클랜마크가 은은하게 빛난다. 계속 빛나고 있어야 한다** (한 번 반짝이고 마는 것이 아니다).

> `[미확인]` 30% 의 분모가 무엇인가 — 병영수첩 클랜원 명단 전체인가, 우리가 아는 선수인가.
> 명단을 아직 수집하지 못했다 (D-219). 분모가 정해져야 계산할 수 있다.

## 4. 본인 인증 — **칭호(title) 인증** (2026-08-31 사용자 채택)

사용자가 처음 제안한 것은 **병영수첩 방명록에 인증코드 쓰기** 였다. 그런데 그 방법은
**우리가 자동으로 검증할 수 없다** — 서버가 병영수첩을 부르면 403 이다(WAF · D-200).
사람이 눈으로 확인하는 수동 승인이 되어 버린다.

그래서 대안을 제안했고 사용자가 채택했다 (*"2번존나 좋다"*).

```
① 가입하면 우리가 칭호 하나를 지정한다   "칭호를 『○○』 로 바꿔 주세요"
② 사용자가 인게임에서 칭호를 바꾼다      무료 · 즉시 · 되돌릴 수 있다
③ 우리가 user/basic 을 폴링해 확인       GET /suddenattack/v1/user/basic → title_name
④ 맞으면 자동 인증 완료                  사람 개입 없음
⑤ 인증 뒤에는 칭호를 원래대로 돌려도 된다
```

근거: `user/basic` 응답에 `title_name` 이 있다 (2026-08-31 실응답 확인).
같은 엔드포인트가 `user_name` · `clan_name` 도 주므로 **감시 기계를 그대로 쓴다**
(`nexon identity-watch` · D-220).

> `[미확인]` 칭호 변경이 API 에 얼마나 빨리 반영되는지 아직 안 재봤다.
> 닉 변경은 몇 분 안에 반영되는 것을 확인했으니(D-220) 비슷할 가능성이 높지만 **확인이 필요하다.**

> `[미확인]` 지정할 칭호 풀. 사용자가 **보유한 칭호 중에서만** 고를 수 있으므로,
> 누구나 갖고 있는 흔한 칭호여야 한다. 어떤 칭호가 그런지 조사해야 한다.

> ⚠ **닉네임으로 인증하지 않는다.** 닉은 식별자가 아니다 (D-220) — 세 명 중 한 명이 바꿨고,
> 옛 닉은 남이 물려받는다. 인증의 기준은 언제나 `ouid` 다.

## 5. 화면 배치

### 5-1. 메인페이지 알 모음집

플레이어 검색 **바로 밑**에, **리그별로 두 벌**을 만든다. **DPL 이 먼저**, 그 아래 IPL.

```
        ○ ○ ○ ○ ○ ○ ○        ← 윗칸
      ○ ○ ○ ○ ○ ○ ○ ○ ○      ← 가운뎃칸 (위·아래보다 조금 더 길다)
        ○ ○ ○ ○ ○ ○ ○        ← 아랫칸
```

- 3칸이고, 맨 위와 맨 아래는 **같은 길이**, 가운데만 **조금 더 길다** (`<>` 모양)
- 알 하나가 클랜 하나다. **클랜마크를 알이 덮는다**
- **알 밑에 클랜명을 쓴다** — 유저가 자기 클랜을 찾아야 깨러 오기 때문이다

### 5-2. 개인랭킹 · 개인기록

같은 방식이다. 전부 알로 덮고 **밑에 닉네임만** 띄운다.

닉네임은 **본닉이 바뀌면 즉시 반영**한다 (`identity-watch` 가 몇 분 안에 잡는다).

> ⚠ **위장닉은 반영할 수 없다.** D-221 에서 불가능으로 확정됐다 — Open API 가 위장닉을
> 모르고, 아는 창구는 병영수첩뿐인데 그게 우리 출처다. 사용자도 이 한계를 받아들였다
> (*"1번은 ㄱㅊ아 그정도면 오키"*).

## 6. 만들 순서

```
1. 알 데이터 모델        개인 알 · 클랜 알 · 깨짐 상태 · 30% 계산
2. 칭호 인증             가입 → 칭호 지정 → 폴링 확인 → 인증
3. 가림 규칙             2장 표를 화면 전체에 적용. 판수·경기상세는 그대로 둔다
4. 메인 알 모음집        5-1 배치
5. 개인랭킹·기록 알       5-2
6. 깨짐 연출             클랜마크 은은한 상시 발광
7. 클랜마스터 직접 깨기
```

1·2 가 먼저다 — 나머지는 전부 "깨졌는가" 를 물어야 그릴 수 있다.
