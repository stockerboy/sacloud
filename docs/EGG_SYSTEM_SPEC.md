## 2. 알이 가리는 것 / 안 가리는 것

**핵심 원칙: 판수와 경기 상세기록은 가리지 않는다.** 있다는 것은 보여 주고, 얼마나 잘하는지를 가린다.

| | 알이 있을 때(안 깨짐) | 알이 깨졌을 때 |
|---|---|---|
| 판수 | **보인다** | 보인다 |
| 경기 상세기록 | **보인다** | 보인다 |
| 승률 | 가린다 | 보인다 |
| N승 N패 | 가린다 | 보인다 |
| 6각형 (개인·클랜) | 가린다 | 보인다 |
| 킬뎃 | **DPL 은 가린다** · IPL 은 해당 없음(원래 없다) | 보인다 |
| 그 밖에 우리가 만든 지표 | 가린다 | 보인다 |

가린 자리에는 **"알이 깨지면 기록을 볼 수 있습니다"** 를 띄운다. 빈칸으로 두지 않는다 —
비어 있으면 없는 줄 알지만, 문구가 있으면 궁금해진다.

> `[미확인]` "우리가 만든 또 다른 추가적 기능들" 의 정확한 목록. 지금 있는 것 기준으로는
> 플레이스타일 바 · 포지션 · 라운드 지표 · 오늘 기록이 후보다. 사용자 확인이 필요하다.

## 3. 알을 깨는 법

```
개인 알   본인이 가입하고 **본인 인증**에 성공하면 자기 알이 깨진다
클랜 알   그 클랜원의 **30% 이상**이 각자 알을 깨면 클랜 알이 깨진다
          ─ 또는 ─
          **클랜마스터**가 본인 인증에 성공하면 **혼자서도** 클랜 알을 깬다
```

깨진 클랜은 **클랜마크가 은은하게 빛난다. 계속 빛나고 있어야 한다** (한 번 반짝이고 마는 것이 아니다).

> `[미확인]` 30% 의 분모가 무엇인가 — 병영수첩 클랜원 명단 전체인가, 우리가 아는 선수인가.
> 명단을 아직 수집하지 못했다 (D-219). 분모가 정해져야 계산할 수 있다.

## 4. 본인 인증 — **칭호(title) 인증** (2026-08-31 사용자 채택)

사용자가 처음 제안한 것은 **병영수첩 방명록에 인증코드 쓰기** 였다. 그런데 그 방법은
**우리가 자동으로 검증할 수 없다** — 서버가 병영수첩을 부르면 403 이다(WAF · D-200).
사람이 눈으로 확인하는 수동 승인이 되어 버린다.

그래서 대안을 제안했고 사용자가 채택했다 (*"2번존나 좋다"*).

```
① 가입하면 우리가 칭호 하나를 지정한다   "칭호를 『○○』 로 바꿔 주세요"
② 사용자가 인게임에서 칭호를 바꾼다      무료 · 즉시 · 되돌릴 수 있다
③ 우리가 user/basic 을 폴링해 확인       GET /suddenattack/v1/user/basic → title_name
④ 맞으면 자동 인증 완료                  사람 개입 없음
⑤ 인증 뒤에는 칭호를 원래대로 돌려도 된다
```

근거: `user/basic` 응답에 `title_name` 이 있다 (2026-08-31 실응답 확인).
같은 엔드포인트가 `user_name` · `clan_name` 도 주므로 **감시 기계를 그대로 쓴다**
(`nexon identity-watch` · D-220).

> `[미확인]` 칭호 변경이 API 에 얼마나 빨리 반영되는지 아직 안 재봤다.
> 닉 변경은 몇 분 안에 반영되는 것을 확인했으니(D-220) 비슷할 가능성이 높지만 **확인이 필요하다.**

> `[미확인]` 지정할 칭호 풀. 사용자가 **보유한 칭호 중에서만** 고를 수 있으므로,
> 누구나 갖고 있는 흔한 칭호여야 한다. 어떤 칭호가 그런지 조사해야 한다.

> ⚠ **닉네임으로 인증하지 않는다.** 닉은 식별자가 아니다 (D-220) — 세 명 중 한 명이 바꿨고,
> 옛 닉은 남이 물려받는다. 인증의 기준은 언제나 `ouid` 다.

## 5. 화면 배치

### 5-1. 메인페이지 알 모음집

플레이어 검색 **바로 밑**에, **리그별로 두 벌**을 만든다. **DPL 이 먼저**, 그 아래 IPL.

```
        ○ ○ ○ ○ ○ ○ ○        ← 윗칸
      ○ ○ ○ ○ ○ ○ ○ ○ ○      ← 가운뎃칸 (위·아래보다 조금 더 길다)
        ○ ○ ○ ○ ○ ○ ○        ← 아랫칸
```

- 3칸이고, 맨 위와 맨 아래는 **같은 길이**, 가운데만 **조금 더 길다** (`<>` 모양)
- 알 하나가 클랜 하나다. **클랜마크를 알이 덮는다**
- **알 밑에 클랜명을 쓴다** — 유저가 자기 클랜을 찾아야 깨러 오기 때문이다

### 5-2. 개인랭킹 · 개인기록

같은 방식이다. 전부 알로 덮고 **밑에 닉네임만** 띄운다.

닉네임은 **본닉이 바뀌면 즉시 반영**한다 (`identity-watch` 가 몇 분 안에 잡는다).

### ⛔ 위장닉은 **쓰지 않는다** — 한계가 아니라 **정책이다** (2026-08-31 사용자 확정)

> "그냥 위장닉은 무시하고 본닉만 적어 무조건 본닉 바뀌기 전에는 닉네임은 본닉으로만 고정이다"

```
표시 이름의 출처는 **Open API 의 본닉 하나뿐이다**  (NexonIdentity.userName)
배틀로그의 `user_nick` 은 **표시에 쓰지 않는다** — 거기에는 위장닉이 섞여 있다
본닉이 바뀌기 전까지 화면의 이름은 **고정**이다
```

D-221 에서 "위장닉은 Open API 에 없어 반영 불가" 로 확정됐는데, 사용자가 그것을 **정책으로
승격**시켰다. 그래서 이제 이건 결함이 아니다 — 위장닉을 못 보는 게 아니라 **안 보는 것**이다.

⚠ 배틀로그 닉을 화면에 쓰면 안 된다. 같은 사람이 화면마다 다른 이름으로 보이게 된다.
   배틀로그 닉은 **계정을 잇는 용도**로만 쓴다 (`barracks-link`).

### 7-2. 어디를 가렸는가

2장 표를 그대로 적용했다. **판수와 경기 상세기록은 어디서도 가리지 않는다.**

| 화면 | 보인다 | 가린다 |
|---|---|---|
| 개인랭킹 | 순위 · 닉네임 · 래더 | 승률 · N승N패 · 킬뎃 · 평균킬 |
| 클랜랭킹 | 순위 · 클랜명 · 래더 | 승률 · N승N패 |
| 개인 기록실 | **경기 카드 목록** · 래더 · 랭킹 · 소속 · 포지션 · MVP · 같이한 플레이어 | 전투력 육각형 · 플레이스타일 · 최근매치 요약(오늘 포함) · 티어별 게임빈도 · 승률 · 킬뎃 · 평균킬 |
| 클랜 기록실 | **경기 카드 목록** · 래더 · 부리그 · 순위 · 포지션별 명단 | 클랜 육각형 · 라운드 지표 · 클랜 지표 · 최근매치 요약 · 승률 · N승N패 |
| 플레이어 프로필 | **전적(판수)** · 래더 · 순위 | 승/패 · 승률 · 킬뎃 · 승패 막대 |
| 클랜 프로필 | **전적(판수)** · 래더 · 순위 · 부리그 | 승/패 · 승률 · 승패 막대 |

- 랭킹 표처럼 좁은 칸은 `▨▨` 로 바꾸고 문구는 표 아래 안내줄에 **한 번만** 적는다.
  칸마다 한 문장을 넣으면 표가 무너진다.
- 큰 덩어리(육각형 · 지표 카드)는 **자리와 크기를 그대로 두고** 흐리게 덮은 뒤 그 위에
  「알이 깨지면 기록을 볼 수 있습니다」를 얹는다. 빈칸으로 두지 않는다.

> `[미확인]` 2장의 *"그 밖에 우리가 만든 지표"* 의 정확한 목록. 지금은 **지표성 카드**까지
> 가리고 **관계 정보**(최근 같이한 플레이어)는 가리지 않았다. 사용자 확인이 필요하다.
>
> `[미확인]` **지난시즌** 화면(`SeasonTable`)은 아직 안 가렸다. 사양에 언급이 없다.

⚠ **가림은 화면에서만 한다.** 서버는 값을 그대로 내려보내고 있어서, 개발자도구를 열면
가린 숫자가 보인다. 진짜로 막으려면 **API 가 안 내려보내야** 하고 그건 DB 작업이다.
홍보 장치로서는 지금으로 충분하지만, 「못 보게 막았다」고 말하면 안 된다.

### 7-3. ⚠ 깨짐 판정은 **임시 배선**이다

> **⚠ 정정 (2026-09-01 · D-222)** — 아래 서술은 **절반만 맞다.**
> 이제 판정이 두 갈래이고 `EggBoot` 은 **둘의 합집합**을 쓴다.

### 7-5. 서버가 기억한다 (2026-09-01 · D-222)

깨짐을 **매번 계산하지 않는다.** `EggBreak` 표에 한 줄로 남긴다.
그래야 「누가 · 언제 · 왜 깼는지」가 남고, **관리자가 시험 삼아 깬 것**과
**본인이 인증해서 깬 것**을 갈라낼 수 있다.

```
DB        EggBreak(targetKind, targetId, reason, brokenByUserId, note, brokenAt)
공개       GET    /api/eggs/broken              → { players: [...], clans: [...] }
관리자      GET    /api/admin/eggs?kind=&league=&query=   목록 + 깨짐 상태 + 사유
           POST   /api/admin/eggs/{kind}/{id}   깬다   (reason='admin', 감사 로그)
           DELETE /api/admin/eggs/{kind}/{id}   되돌린다 (지우면 다시 잠긴다)
화면       /admin/eggs                          찾아서 한 줄씩 깨고 되돌린다
```

**공개 쪽은 식별자만 준다.** 사유(`reason`)와 시각(`brokenAt`)은 내려보내지 않는다 —
깨짐 여부는 화면에 이미 보이지만 **근거는 관리자 것**이다.
이 경계는 시험으로 고정돼 있다 (`apps/web/tests/eggApi.test.ts`).

**`reason='admin'` 은 진짜 근거가 아니다.** 칭호 인증(4장)이 들어오면 그 줄만 골라
지우면 되고, 인증으로 깬 것은 남는다. 이미 깨져 있는 알을 다시 눌러도
**사유를 덮지 않는다** — 인증 기록이 관리자 기록으로 바뀌면 안 되기 때문이다.
