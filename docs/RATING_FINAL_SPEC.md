## 0. 설계 철학 (한 문단)

제3보급창고 클랜전에는 **자동 매치메이킹이 없다.** 상대를 사람이 직접 고른다.
그래서 점수 공식이 매칭 필터 역할까지 해야 한다. 단순 승률로는 안 된다.

> **강한 상대들과 많이 싸우고, 그 강한 상대들을 실제로 많이 이긴 사람이 가장 높이 간다.**

중요도 순서는 다음과 같고 **뒤집지 않는다.**

```
상대 강도 → 승패 → 강한 상대를 상대로 만든 승리 → 충분한 경기 수 → 지속적 활동 → (KD/MVP 는 점수에 없음)
```

## 1. 개인 레이팅

### 1-1. 내부 Elo (실력 추정치)

```
기대 승률   E = 1 / (1 + 10^((상대 - 나) / 400))
증감        Δ = K × (실제 − E)              실제: 승=1, 패=0
K = 50 · 기준점 3000 · 제로섬 · 바닥 1000
```

- **제로섬이다.** 내가 얻은 만큼 상대가 잃는다. 점수 총량은 늘어나지 않는다.
- 배치고사(1~10경기) 구간의 Δ 는 **0** 이다.
- KD · 데미지 · 헤드샷 · MVP · 탈주 · 연승연패는 **식에 들어가지 않는다.**

### 1-2. 약팀 사냥 차단선 ★ 신규

```
if (승리 && E >= 0.90)  Δ = 0
패배는 언제나 그대로 손해다.
```

E ≥ 0.90 은 상대보다 **약 382점 위**라는 뜻이다.

**왜 필요한가.** 순수 Elo 는 "3100 상대 95% 승" 과 "3500 상대 60% 승" 을 같게 본다.
매치메이킹이 있는 환경이면 맞는 말이지만, 상대를 고를 수 있는 제3보급에서는
약팀만 골라 잡아 4,876 까지 올라갈 수 있었다 — 강한 상대를 **한 번도 이기지 않고서**.

이 선을 두면 양학의 상한이 **"내가 사냥하는 팀 중 가장 센 팀 + 382"** 로 고정된다.
별도의 "강팀전 보너스" 를 만들지 않고 expected-score 하나로 해결한다.

**정직한 일정은 한 점도 손해 보지 않는다.** 강일정 55% · 최상위 50/60/70% · 혼합 62% ·
300판 58% · 500판 55% · 150판 60% · 40판 75% 를 차단선 유무로 비교했을 때 **전부 동일**했다
(회귀 테스트로 고정). 0.85 까지 내리면 정상 일정도 깎이기 시작하므로 0.90 이 경계다.

### 1-3. 신뢰도 (표시 점수에만)

| 경기 수 | 신뢰도 |
|---|---|
| 1 ~ 30 | 40% |
| 31 ~ 60 | 55% |
| 61 ~ 90 | 70% |
| 91 ~ 120 | 85% |
| 121 ~ 149 | 95% |
| 150 이상 | 100% |

- 내부 Elo 는 신뢰도의 영향을 **받지 않는다.** 표시 점수를 만들 때만 곱한다.
- **150경기 이후 판수 자체로 주는 보너스는 없다.** 많이 하는 이점은
  "실력을 더 확실히 증명할 기회가 많다" 뿐이다.

### 1-4. 표시 점수

```
표시(감점 전) = 3000 + (내부 − 3000) × 신뢰도 × 3.5
표시(최종)    = 표시(감점 전) − 활동 페널티
```

- **percentile 앵커를 쓰지 않는다.** "상위 0.5% 는 자동 4300" 같은 상대평가는 금지다.
  압도적인 시즌도 4300 이 되고 약한 시즌의 1등도 4300 이 되어, 점수를 **버는** 구조가 사라진다.
- 고정 선형식이다. piecewise · convex 와 비교했을 때 실력 재현도가 **셋 다 같았고**,
  convex 는 4900/5000 희귀성을 무너뜨렸다. 정확도가 같으면 설명 가능한 쪽을 고른다.
- **hard cap 이 없다.** 5000 을 넘을 수 있다.

### 1-5. 점수대 의미

| 점수 | 의미 | 9시즌 관측 |
|---|---|---|
| 3000 | 시작 / 기준 | — |
| 3500 | 꽤 잘하는 선수 | — |
| 4000 | 확실한 랭커 | 9/9 시즌 (5~22명) |
| 4100 | "41층" · 분명한 상위권 | 9/9 시즌 (4~18명) |
| 4300 | 매우 강한 상위권 | 9/9 시즌 (1~10명) |
| 4500 | 최상위권 | 6/9 시즌 (0~5명) |
| 4700 | 극상위 | 3/9 시즌 (0~5명) |
| 4800 | 매우 희귀 | 1/9 시즌 (0~3명) |
| 4900 | 역사적인 시즌 | 0/9 — 정상 시즌에서는 안 나온다 |
| 5000+ | hard cap 아님 · 역대급만 | 0/9 · 합성 outlier 는 **5,638** 도달 |

### 1-6. 미참여 감점 (활동 페널티)

**내부 Elo 를 깎지 않는다.** 한 달 쉬었다고 실력이 사라진 것은 아니다.
사라진 것은 **현재 왕좌를 지킬 자격**이다. 그래서 실력 추정치와 활동성을 분리한다.

```
활동 페널티는 표시 점수에서만 뺀다.
구간은 "감점 전 표시 점수" 기준. 하루 단위로 (주간 감점 ÷ 7) 씩 쌓인다.
```

| 감점 전 표시 점수 | 유예 | 주당 감점 |
|---|---|---|
| 4900 이상 | 7일 | −60 |
| 4800 ~ 4899 | 7일 | −50 |
| 4600 ~ 4799 | 7일 | −40 |
| 4300 ~ 4599 | 7일 | −30 |
| 4000 ~ 4299 | 10일 | −20 |
| 4000 미만 | — | **없음** |

- 구간이 표시 점수 기준이라 **내려갈수록 감점 속도도 느려진다** — 자동으로 자기 제한이 걸린다.
- **바닥은 3000.** 감점만으로 기준점 아래로 내려가지 않는다.
- 4000 미만 유저는 아무리 쉬어도 **0점** 깎인다.

**실측 (잠수 일수별 손실)**

| 시작 | 1주 | 2주 | 3주 | 4주 | 6주 |
|---|---|---|---|---|---|
| 4200 | −0 | −14 | −34 | −54 | −94 |
| 4500 | −4 | −34 | −64 | −94 | −154 |
| 4800 | −7 | −47 | −87 | −127 | −206 |
| 4900 | −9 | −59 | −107 | −147 | −227 |

### 1-7. 복귀 — "1판 던지기" 로 초기화되지 않는다 ★

```
경기 1판당 활동 페널티 −8 회복. 그 이상은 회복되지 않는다.
```

경기를 하면 페널티가 **더 쌓이는 것은** 멈추지만, 이미 쌓인 것은 남는다.

| 상황 | 쌓인 페널티 | 완전 회복에 필요한 경기 |
|---|---|---|
| 4800 · 28일 잠수 | 127 | **16경기** |
| 4800 · 42일 잠수 | 206 | **26경기** |
| 4900 · 35일 잠수 | 187 | **24경기** |
| 4500 · 28일 잠수 | 94 | **12경기** |

한 판만 던져서 왕좌를 지키는 경로는 없다.

### 1-8. 개인 퍼포먼스 — **0%** (넣지 않는다)

시드 3개로 0% / ±2% / ±5% 를 비교했다.

| 비중 | 실력 재현도 | 일정 감안 승리의 질 |
|---|---|---|
| 0% | 0.9066 / 0.9173 / 0.8915 | **0.987 / 0.982 / 0.979** |
| ±2% | 0.9076 / 0.9179 / 0.8929 | 0.973 / 0.969 / 0.973 |
| ±5% | 0.9087 / 0.9191 / 0.8938 | 0.903 / 0.915 / 0.921 |

±2% 는 실력 재현도를 **+0.001** 올리는 대신 1순위 지표를 **−0.011** 내린다.
세 시드 모두 같은 방향이다. **1순위 지표를 더 많이 깎으면서 사는 거래**이므로 채택하지 않는다.

KD · MVP 는 **프로필 통계로만** 보여 준다. 덕분에 설명이 한 문장으로 끝난다 —
**"킬뎃은 점수에 들어가지 않는다."**

## 2. 클랜 레이팅

### 2-1. Clan Elo

개인과 같은 식이다. 상대는 **상대 클랜의 레이팅**이다.

```
E = 1 / (1 + 10^((상대클랜 − 우리클랜) / 400))
Δ = 50 × (실제 − E)     제로섬 · 기준점 3000
```

### 2-2. 구성 보정 (상한 있음)

```
최근 20경기의 평균 본클랜원 수 → 보정 점수
클랜 최종 점수 = Clan Elo + 구성 보정 − 클랜 활동 페널티
```

| 최근 20경기 평균 본클랜원 | 보정 |
|---|---|
| 1.0 | **+0** |
| 2.0 | +10 |
| 3.0 | +20 |
| 4.0 | +35 |
| 5.0 | **+50** (상한) |

사이 값은 선형 보간.

- **판수로 누적되지 않는다.** 몇 판을 하든 최대 +50 이다.
- 상한 스윕 결과 (클랜 실력 재현도): 상한 0 → 0.8832 · 30 → 0.8762 · **50 → 0.8726** ·
  70 → 0.8672 · 100 → 0.8644. 상한이 클수록 정확도가 떨어진다.
  **50** 은 유도 강도와 정확도의 균형점이고, 실력 차이를 뒤집을 만큼 크지 않다.
- 창 크기 10 / 20 / 30 / 50 은 결과 차이가 거의 없어 **설명하기 쉬운 20** 으로 고정한다.

### 2-3. 클랜 미참여 감점

개인과 **다른 표**를 쓴다. 클랜은 한 사람이 아니라 조직이라 기준이 짧아도 된다.

| 무경기 기간 | 주당 감점 |
|---|---|
| 0 ~ 6일 | 없음 |
| 7 ~ 13일 | −10 |
| 14 ~ 20일 | −20 |
| 21일 이상 | −30 |

- 경기 1판당 **−5** 회복. 바닥은 3000.
- 목적은 점수 파괴가 아니라 **active leaderboard 의 의미 유지**다.

## 3. 대상 판정 (eligibility) — official 게이트 **폐기**

### 3-1. 확정 정책

```
정상적인 제3보급창고 5v5 + 실제 참가자 10명  →  레이팅 대상.
```

- **`homeClanMembers >= 3 OR awayClanMembers >= 3` 게이트를 폐기한다.**
- **`unofficial 이라 rating 0` 은 없앤다.**
- **클랜원 가중치 `{full:1, two:0.7, one:0.4, none:0}` 을 폐기한다.** 전부 1.0 이다.
- official / unofficial 은 **UI·통계용 historical label 로만** 남길 수 있다.

**왜.** 제3보급 인원이 많지 않은 상황에서 "클랜원 3명 못 채우면 점수 없음" 은
사용자를 랭킹에서 이탈시킨다. **열빡을 죽이지 않는다. 진짜 클랜전을 더 가치 있게 만든다.**

### 3-2. 점수 처리 예시

| 경기 | 개인 점수 | 클랜 점수 | 구성 보정 |
|---|---|---|---|
| 클1용4 vs 클1용4 | **지급** | **지급** | 양쪽 +0 |
| 클2용3 vs 클3용2 | 지급 | 지급 | +10 / +20 |
| 클5 vs 클5 | **지급** | **지급** | 양쪽 **+50** |
| 클5 vs 클1용4 | 지급 | 지급 | +50 / +0 |

같은 Elo 라면 클5 클랜이 클1 클랜보다 **최대 50점 위**에 있다. 그뿐이다.

## 4. 반복 대진 / 파밍 대응

**자동 감쇠를 넣지 않는다. 탐지만 한다.**

멸망전 20 / 50 / 100 연전과 재편 시나리오에서 **생성된 점수 총합은 전부 0.00** 이었다.
Elo 가 제로섬이라 반복 대전으로 점수가 새로 생기지 않는다.
후반 평균 |Δ| 는 23.6 → 20.2 → 14.4 로 수렴한다.

| 시나리오 | 점수 총합 증가 | 평균 본클랜원 |
|---|---|---|
| 고정팀 (클5 vs 클5) 100판 | 0.00 | 5.00 |
| 20판마다 재편 | 0.00 | 3.40 |
| 5판마다 재편 | 0.00 | 3.35 |
| 소속 분산 열빡 | 0.00 | 2.00 |

열빡 재편은 **구성 보정만** 자연히 낮아진다 (5.00 → 2.00 → 보정 +50 → +10).
탐지 알고리즘 없이 구조적으로 나오는 결과다.

→ **정상적인 라이벌전까지 벌하는 복잡한 규칙을 넣지 않는다.**
   같은 상대와의 대전 횟수는 **관리자 탐지 플래그**로만 집계한다.

## 5. 결정적 재현 (deterministic replay)

- 정렬: `startAt` 오름차순 → 같으면 `matchId` 오름차순 (안정 정렬).
  `startAt` 은 `matchId` 앞 12자리(KST)에서 유도한다.
- 레이팅은 **경기 시각 순서대로** 재생한다. 수집 시각·저장 순서를 쓰지 않는다.
- 경기 당시 소속(`match-time affiliation`)으로 판정한다. 현재 소속을 쓰지 않는다.
- 미참여 감점 tick 은 **하루 단위**로 돌리고, 경기 재생과 시간순으로 섞는다.
- 반올림: 내부 Elo 는 **실수로 유지**하고, 표시 점수만 `roundHalfUp` 으로 정수화한다.
  (경기마다 반올림하면 오차가 누적되어 제로섬이 깨진다.)
- `formulaVersion` 을 모든 `rating_update` 에 남긴다. 최종안은 **`sacloud-v1`**.

## 6. 엣지 케이스

| 상황 | 처리 |
|---|---|
| 참가자가 10명이 아님 | 레이팅 제외. 기록은 남긴다 |
| 같은 선수가 양 팀에 | 레이팅 제외 · 관리자 플래그 |
| 배치고사(1~10경기) | Δ = 0 · 랭킹 미표시 · 래더 자리에 `배치고사` |
| 상대 클랜을 알 수 없음 | 개인 레이팅만 반영 · 클랜 레이팅 제외 |
| 탈주 | 레이팅에 반영하지 않는다 (승패만 본다) |
| 무기(라이플/스나이퍼) | **계산에 영향 없음.** `sniper_rating_delta` / `rifle_rating_delta` 로 **기록만** 분리 |
| 통합 래더 | `base + sniper_delta + rifle_delta`. 무기 분리가 통합값을 바꾸면 안 된다 |
| 과거(3rd.supply) 경기 | `rating_update` 를 **재계산하지 않는다.** 원본값 보존 |
| 신규 선수 | 3000 에서 시작 · 신뢰도 40% |
| 시즌 전환 | 개인·클랜 모두 3000 에서 다시 시작 (soft reset 없음) |

## 7. 사용자에게 하는 설명 (이 이상 복잡해지면 다시 단순화한다)

> 강한 상대를 이기면 많이 오르고, 약한 상대를 이기면 적게 오른다. 지면 반대로 떨어진다.
> **너무 약한 상대를 이기면 아예 오르지 않는다.**
> 판수만 많다고 오르지 않는다.
> 킬뎃과 MVP 는 점수에 들어가지 않는다 — 프로필 기록으로만 남는다.
> 150경기까지는 아직 검증 중이라 점수가 완전히 열리지 않는다.
> 높은 점수를 찍은 뒤 오래 안 하면 미참여 감점이 있고, 한 판만 해서는 되돌릴 수 없다.
> 클랜은 용병을 많이 써도 점수를 받는다. 다만 자기 클랜원을 꾸준히 데리고 나오면 조금 더 높게 평가한다.

## 9. 운영 데이터 replay 계획 (실행 금지 — 다음 작업)

1. **보존.** `rating_update` · `ratingAfter` · `formulaVersion` 을 통째로 스냅샷 테이블에 복사한다.
   raw/staging 은 절대 건드리지 않는다.
2. **새 버전.** 신규 계산은 `formulaVersion = "sacloud-v1"`. 과거 3rd.supply 이관분은
   `origin = "3rd.supply"` 로 두고 **재계산하지 않는다.**
3. **재생.** `startAt` → `matchId` 순으로 모든 complete 5v5 를 시간순 재생.
   경기 당시 소속으로 본클랜원 수를 세고, 미참여 감점 tick 을 하루 단위로 섞는다.
4. **대상 전환.** 기존 `official=false` 경기도 전부 레이팅 대상으로 올린다.
   `official` 컬럼은 label 로만 남긴다.
5. **incomplete 88건.** 여전히 제외한다. 넥슨 할당량 회복 후 backfill 되면 그때 다시 재생한다.
   **억지로 complete 처리하지 않는다.**
6. **용병.** 소속과 무관하게 개인 레이팅을 받는다. 클랜 레이팅에는 그 경기의 클랜만 반영한다.
7. **대조.** before/after 를 나란히 저장하고 ① 총합 제로섬 ② 상위 50명 순위 변동
   ③ 밴드 분포 ④ 배치고사 인원 을 숫자로 대조한다.
8. **rollback.** 스냅샷 테이블에서 되돌린다. 마이그레이션은 additive 만 —
   `prisma migrate dev` 금지 · reset 금지.

## 10. 남은 미확정

**없다.** 이번 작업에서 4가지(표시 함수 · 감점 · 구성 상한 · 퍼포먼스)를 모두 확정했다.

운영 반영 시 재보정이 필요할 수 있는 값은 아래 하나뿐이며, 이는 미확정이 아니라
**실데이터 확인 항목**이다.

- 시뮬레이션 모집단에는 매치메이킹이 없어 상위 승률이 88~95% 로 극단적이다.
  실제 Beta 데이터로 replay 한 뒤 **밴드 절대값(4000/4500/4800)이 의도한 인원 비율과 맞는지**
  한 번 확인한다. 어긋나면 **표시 배율 3.5 하나만** 조정한다. 다른 상수는 건드리지 않는다.
