# SACLOUD 프로젝트 — 지금까지의 과정과 반복된 문제

> 외부 AI에게 상황을 설명하기 위해 정리한 문서.
> 작성 2026-09-04. 비밀번호·토큰·개인정보는 뺐다.

---

## 1. 이건 뭐 하는 프로젝트인가

**서든어택(FPS 게임) 클랜전 기록 사이트.** 주소는 `3rdcloud.my`.

목표는 기존 사이트 `3rd.supply`를 **완전히 대체**하는 것.
거기 유저가 2~3천 명 있고, 우리 쪽은 아직 거의 없다.

사람이 오는 이유는 넷뿐이다:
① 요즘 누가 잘하는지 ② 어느 클랜이 1티어인지 ③ 내 기록 ④ 친구 기록

### 리그가 셋이다 (화면 이름과 내부 이름이 다름)

| 화면 이름 | 내부 slug | 자료 출처 |
|---|---|---|
| SPL | `supply` | 3rd.supply 미러 (남의 사이트에서 긁어옴) |
| IPL | `nolink` | **넥슨 병영수첩에서 직접** |
| 10mountain | `sanply` | 3rd.supply 미러 |
| (대룰) | `daerule` | 닫음. 보존만 |

**리그는 서로 완전히 분리된다.** IPL 경기는 IPL 끼리 해야만 기록된다.
클랜은 한 리그에만 속한다.

### 프로젝트의 핵심 목표 (사장님이 못박은 것)

> "서플라이에서 이미 긁어온 자료는 사용해도 된다. 하지만 우리도 우리만의 수집도구와
> 체계가 있어야 한다. 반드시 실시간으로 어떤 정보도 누락 없이 가져올 도구가 있어야 한다.
> **서플에 의존하는 카피 사이트를 만드는 게 아니다.**"

즉 **남의 사이트에서 긁어오는 걸 끊고, 넥슨에서 직접 받아오는 것**이 최종 목표.

## 2. 기술 구성

```
Next.js 15 (App Router) · React 19 · TypeScript 5.9 · pnpm 모노레포
배포     Vercel (main 브랜치 = 운영) · 서울 리전
DB       Supabase (PostgreSQL) · 서울 리전
자동화   GitHub Actions

apps/web/          화면 + API
apps/worker/       수집 잡 + CLI
packages/contract/ Zod 스키마 (계약의 단일 진실)
packages/db/       Prisma 스키마
packages/ui/       공용 컴포넌트 + 디자인 토큰
packages/nexon/    넥슨 API 클라이언트
```

개발 환경은 **윈도우 노트북 8GB 한 대**. 사람은 한 명(사장님)이고,
AI 세션 두 개(기획/실행)와 보조 에이전트 몇이 붙어 작업한다.

## 3. 지금까지 한 것

### 자료 수집

- 3rd.supply 미러로 SPL·10mountain 경기 약 33만 건 확보 (기존)
- **넥슨 병영수첩에서 IPL 경기를 직접 받는 길을 뚫음** (2026-09-03)
  - IPL 경기 약 26,900건 확보
  - 라인업(누가 뛰었는지) 11% → 23% 진행 중
- 시즌을 넷으로 나눔: legacy(~3/4) · Beta(3/5~7/1) · 시즌0(7/2~9/30) · 시즌1(10/1~)
- 한 클랜이 두 리그에 겹쳐 있던 43곳 정리

### 점수 체계

- Elo 계열 래더 (기준 3000점). 티어 이름 없음
- 공식은 하나. 스나이퍼/라이플용을 따로 만들지 않고 **기록만 무기별로 분리**
- 킬·데스·MVP·딜량은 공식에 안 넣음 (승패와 상대 실력만)
- 통합 순위: 리그마다 권위 가중치를 다르게 두고 **더한다** (가중평균 아님)

### 화면

여섯 개만 유지: 홈 · 선수 · 클랜 · 경기목록 · 경기상세 · 랭킹

## 4. ★반복해서 생긴 문제들★ — 이게 이 문서의 핵심

### 문제 1. AI가 확인하지 않고 단정한다

가장 자주, 가장 크게 손해를 본 유형.

실제 사례:
```
"오라클 클라우드에 서울 리전이 있다"   → 문서엔 있는데 실제 가입 화면엔 없었다
"서버 비용은 월 만원쯤"                → 안 재보고 말함. 무료 등급이 있었다
"사장님은 밤에 컴퓨터를 끄실 것이다"    → 재보니 새벽에도 켜져 있었다
"1,447명 중 44명만 해당"              → 분모도 분자도 틀렸다 (실제 190명)
"병영수첩은 최근 기록만 준다"          → 페이징 파라미터를 못 찾았을 뿐이었다
```

마지막 것이 특히 컸다. 사장님이 **"그건 거짓말이야, 정확하게 알아보고 와"**라고
밀어붙여서 다시 팠더니, 병영수첩 자바스크립트 원문 안에 커서 파라미터가 적혀 있었다.
**API 응답만 보고 "안 된다"고 판정했고, 실제 화면과 네트워크 요청은 안 봤다.**

### 문제 2. "됐습니다"인데 화면엔 없다

```
"선수 화면을 새 톤으로 바꿨습니다"   → 실제로는 배경색만 바뀌고 나머지는 그대로
"실선 규칙을 확정했습니다"          → 계약(스키마)에만 있고 화면 코드가 그걸 안 읽고 있었다
"자동수집이 15분마다 돕니다"        → 그때 이미 두 번 실패 중이었다
```

원인: **만든 결과를 눈으로 확인하지 않았다.**
AI 세션에 브라우저가 없어서 코드와 숫자로만 판단했다.

### 문제 3. 숫자를 세는데 기준이 틀렸다

```
· 색 대비를 잴 때 → "패널 배경" 기준으로 쟀는데 실제 글자는 다른 배경 위에 있었다
· 비율을 낼 때   → 분모에 "그 기간에 활동 안 한 사람"까지 넣었다
· 리그별 비율    → 어느 리그 기준인지 안 밝혀서 같은 값이 89.7% 와 37.3% 로 갈렸다
· "#hex 64곳 발견" → 세어보니 주석 16 + 폴백 46 이라 실제 고칠 자리는 0곳
```

교훈으로 만든 규칙: **"숫자를 받으면 그게 무엇을 센 것인지 되묻는다.
그리고 센 것 중 결론과 상관없는 게 몇 개인지도 센다."**

### 문제 4. 조용한 실패

가장 위험한 유형. **실패했는데 시스템이 "정상"이라고 말한다.**

```
· 수집이 실패했는데 판정 단계가 "정상"을 찍었다
  → 실패한 단계가 그 자리에서 죽어서 결과값을 못 남겼고,
    빈 값이 기본값 "0(성공)"으로 채워졌다

· GitHub Actions 워크플로에서 `inputs.x == false` 를 썼는데
  → push 로 실행되면 inputs 가 null 이고, GitHub 식에서 null == false 가 참이다
  → 후처리 단계가 조용히 꺼졌다. 원문만 쌓이고 화면은 그대로인데 감시자는 초록불

· 알림용 curl 에 실패 감지 옵션이 없어서
  → 웹훅 주소가 틀려 404를 받아도 "보냈다"로 끝났다

· 수집 루프가 다 끝나야 DB에 저장하게 돼 있었다
  → 130건 받고 중간에 죽으니 저장된 게 0건
```

### 문제 5. 프로세스가 안 죽는다

```
"수집을 멈추고 다른 걸 시작했습니다" → 실제로는 안 죽었다
쓰던 도구가 셸만 죽이고 그 아래 실제 프로세스는 남겼다
→ 수집기 두 개가 동시에 돌아 요청 간격이 절반이 됐다 (속도 제한 위반)
→ 두 시간 반 뒤 그 프로세스가 스스로 끝나면서 로그를 남겨서야 알았다
```

교훈: **"멈췄다"는 셸이 죽었다는 뜻이지 일이 멈췄다는 뜻이 아니다.
멈춘 뒤에는 프로세스를 세어 본다.**

### 문제 6. 같은 데이터가 두 출처에서 들어와 겹쳤다

```
미러(3rd.supply)가 이미 넣어둔 라인업 위에
병영수첩 라인업을 또 넣고 있었다

같은 사람이 출처가 달라 서로 다른 행이 되어 겹침을 아무도 못 막았다
→ 한 경기가 10명이 아니라 20명으로 보이고 킬/데스가 두 배로 집계됐다
→ 순위와 킬뎃이 그만큼 틀렸다 (1,111경기)
```

같은 뿌리로, **같은 사람이 두 선수로 갈려 있다** (약 455쌍).
검색하면 같은 닉네임이 두 번 나오고, 기록이 반씩 갈린다.
닉네임으로 합치면 동명이인이 섞이므로 함부로 못 합친다.

### 문제 7. UI를 계속 못 만들었다

**이게 사장님을 가장 지치게 했다.**

```
· 시안을 열 번 넘게 만들었는데 전부 퇴짜
· 원본 스크린샷을 주셨는데도 못 따라했다
· 손으로 그려주신 그림도 못 따라했다
· 결국 "너는 UI에 재능이 아예 없다"는 평가를 받았다
```

**원인은 재능이 아니라 "눈"이었다.**
AI 세션들이 브라우저에 접근할 수 없어서 **만든 결과를 볼 수 없었다.**
색 대비를 숫자로(4.6:1) 맞추는 건 됐는데, "보기에 어떤가"는 판단이 불가능했다.
결국 사람이 매번 눈 역할을 했고 그게 사람의 시간을 태웠다.

나중에 헤드리스 브라우저를 직접 띄워 스크린샷을 찍는 도구를 만들고 나서야
결함 몇 개를 스스로 찾을 수 있게 됐다.

**그 과정에서도 또 틀렸다** — 스크린샷 크기를 390px로 줬는데
레이아웃은 기본 창 크기로 계산돼서, 사진만 보고 "폰에서 화면이 잘린다"고
보고할 뻔했다. **사진이 390px이라고 뷰포트가 390px인 게 아니었다.**

### 문제 8. 문서와 코드가 거짓말을 한다

```
· 운영 절차서에 "208,067행 있음"이라고 적혀 있었는데 그건 로컬 개발 DB 값이었다
  운영은 0행이었다
· 디자인 문서에 적힌 색상 값이 실제 코드와 달랐다 (화면이 이미 바뀌었는데 문서만 안 따라옴)
· 워크플로 파일 주석에 "네트워크를 안 쓴다"고 적혀 있었는데 실제로는 썼다
```

### 문제 9. 개발 환경 자체가 깨져 있었다

```
회사 문서보안 프로그램이 네트워크 소켓을 깬다
· 동시 연결이 많아지면 connect() 가 EFAULT/EINVAL 로 실패 (실패율 24~53%)
· 그리고 listen() 도 깬다 → 로컬 개발 서버가 원천적으로 안 떴다
  (IPv4 리터럴로 바인딩하면 무조건 실패. 호스트를 이름으로 주면 됨)

이걸 몇 달 동안 "와이파이 문제"로 오해하고 있었다
```

## 5. 지금 막혀 있는 것

### 자동 수집을 어디서 돌릴 것인가

넥슨 병영수첩은 **요청하는 쪽에 따라 다르게 반응한다.**

```
집 인터넷 + 평범한 CLI 도구  →  200 (열림) — 120번 불러 거절 0번
집 인터넷 + Node.js fetch    →  403 (막힘) — 같은 IP, 같은 순간
GitHub Actions 실행기        →  403
Vercel 서버리스 (서울)       →  403
```

**클라이언트 지문과 IP 둘 다 걸리는 것으로 보인다.**
왜 갈리는지는 일부러 파지 않았다 — 알아내서 흉내 내면 그건 탐지 회피이기 때문이다.

그래서 지금 남은 방법은 **개인 컴퓨터에서 15분마다 도는 것**뿐이다.
컴퓨터가 켜져 있는 동안만 돈다는 약점이 있다.
(꺼져 있던 동안의 경기도 나중에 켜지면 들어오므로 "기록이 빈다"가 아니라 "늦게 찬다")

### 넥슨 공식 API는 왜 못 쓰나

```
경기 자체는 있다 (「퀵매치 클랜전」이라는 다른 이름으로)
그런데:
· 참가자를 넥슨 내부 ID로만 조회 가능한데 그 ID를 아는 선수가 0.1%
· 한 경기를 열어도 10명이 다 안 온다 (6건 중 2건만 10명)
· 클랜이 4~9개로 온다 (경기 당시가 아니라 현재 소속이라서)
· 무기 정보를 아예 안 준다
```

### 사람을 어떻게 데려올 것인가

기존 사이트에 2~3천 명이 있고 우리는 거의 없다.
지금 검토 중인 방안: **디스코드 봇** — 클랜 디스코드에 봇을 넣어두면
경기가 끝날 때 결과가 자동으로 올라가고, `/전적 <닉네임>` 같은 명령어를 쓸 수 있다.

## 6. 이 프로젝트에서 만든 작업 규칙 (반복 사고로부터)

```
1  확인 안 한 것은 「안 봤습니다」를 붙인다. 짐작을 숫자처럼 말하지 않는다
2  숫자를 받으면 「그게 무엇을 센 것인가」를 되묻는다
   그리고 「센 것 중 결론과 상관없는 게 몇인가」도 센다
3  숫자를 고치면 그 숫자를 인용한 줄까지 따라간다
4  「이게 되면 다 된다」를 작업 순서로 옮기지 않는다
5  판단이 갈릴 때는 「어느 기준이 이기는지」를 먼저 적는다
6  막히면 세 번 안에 「이 길은 비싸다, 대신 이게 있다」를 올린다. 붙들고 노력하지 않는다
7  지우지 않는다. 숨기거나 남긴다 (되돌릴 수 있게)
8  첫 차단(403)에서 멈춘다. 우회하지 않는다
9  「멈췄다」 뒤에는 프로세스를 세어 본다
10 만든 결과를 눈으로 확인하기 전에는 「됐습니다」를 쓰지 않는다
```

## 7. 외부 AI에게 묻고 싶은 것

1. **위 문제 유형들을 구조적으로 줄이는 방법**이 있는가?
   특히 "조용한 실패"와 "확인 안 하고 단정"

2. **AI가 만든 UI를 사람이 매번 눈으로 검사해야 하는 구조**를 어떻게 깰 수 있나?
   (스크린샷 자동화 외에)

3. **클라이언트 지문/IP로 막는 서비스에서, 우회하지 않으면서** 자동 수집을 유지하는
   합법적이고 지속 가능한 방법이 있는가?

4. 기존 서비스 유저 2~3천 명을 **새 서비스로 옮기는 실전적 방법**
