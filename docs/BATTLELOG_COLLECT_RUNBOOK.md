## 2. 시작하는 법

> ⚠ ★★2026-09-03 — 아래 「브라우저로 하는 법」은 더 이상 기본이 아니다★★
>
> 사장님: «★나는 크롬 못켜놓는다★ ★무조건 자동화 방안 알아봐 15분에 한번 갱신되는★»
>
> ★병영수첩은 `curl` 이면 200 이다★ (D-268 실측). Node fetch 는 403 이지만 curl 은 200 이고,
> ★쿠키 한 개 없이 · UA 를 위조하지 않고★ 받았다. 그래서 —
> ```
> 지금  .github/workflows/barracks-collect.yml   ★15분마다 스스로 돈다★
>       pnpm --filter @sacloud/worker nexon barracks-collect --clans 10 --limit 120 --confirm
> ```
> ★아래 스니펫 방식은 지우지 않는다★ (`CLAUDE.md` 10-4) — curl 이 막히는 날 되돌아올 길이다.
> 다만 ★기본은 위쪽이다.★

```
1. 병영수첩 https://barracks.sa.nexon.com 을 열고 **로그인한 채로** 둔다
2. dev 서버가 127.0.0.1:3000 에 떠 있는지 확인한다
   ⚠ `pnpm dev:clean` 을 함부로 돌리지 마라. 다른 세션이 쓰는 서버를 죽인다
3. F12 → Console 에 `scripts/battlelog-collect-snippet.js` **전체**를 붙여 넣는다
4. 아래 한 줄
```

```js
collectBattleLogs({ delay: 500 })      // await 없이 띄워 두고 __blStatus() 로 본다
```

- 1순위만: `collectBattleLogs({ priority: 1, delay: 500 })`
- 조각 하나만: `collectBattleLogs({ part: 'p1-001', delay: 500 })`
- 멈추기: `__blStop()` · 상태 보기: `__blStatus()`

스니펫은 **헤더를 하나도 만들지 않는다** (`credentials: 'include'` 뿐이다).
UA·Referer 를 손으로 짜 넣는 순간 그것은 우회가 된다. 고치지 마라.

## 3. 상한 — 지킨다

```
간격        500ms   (스니펫 기본은 200ms 다. 반드시 delay 를 넘겨라)
총량        오늘 5,153짝. 이 목록 밖으로 나가지 않는다
범위        1순위 · 2순위만
조각        조각이 끝날 때마다 DB 카운트로 대조한다 (CLAUDE.md 3-A 6번)
조각 사이   최소 5초 쉰다 — dev 서버로 POST 가 몰리면 다른 세션 측정이 오염된다
```

> ⚠ **정정 (2026-09-02 · D-266) — 위 「간격 500ms」는 옛 서술이다. 지우지 않는다.**
>
> 2026-09-02 04:24~04:32 UTC 에 집 IP 크롬에서 **delay 400 → 200ms** 로 돌리다
> **296건(fetched 285 · inserted 285 · failed 12)** 만에 연속 5건 403 이 났고 직후 첫 페이지 GET 도
> 403(NEXON 차단 화면)이었다. 500ms 도, 「403 한 번이면 즉시 중단」도 안 지켰다 — 총괄 판단 실수.
>
> **사고 뒤 상한:**
> ```
> 간격        하한 1000ms · 기본 1500ms   (500ms 아니다. 스니펫 기본 200ms 는 절대 그대로 쓰지 마라)
> 403         첫 한 건에서 즉시 정지 — 「연속 N건」을 기다리지 않는다
> concurrency 옵션은 있으나 기본 1. 근거 없이 올리지 않는다
> 재시도      차단 뒤 15분 이상 지나서 1건만 — 풀렸는지 보는 것이지 재개가 아니다
> 하루 상한   [미확인] — 실측으로 정한다
> ```
> 실측 배경: 집 IP 크롬 3건 200 · 빈 프로필도 200(로그인 불필요) · GitHub Actions(Azure IP) 는
> 헤드풀·헤드리스 모두 403. **집 IP 브라우저가 유일한 길이었고 그 길을 속도로 막았다.**

### 즉시 중단 — 하나라도 걸리면 그 자리에서 멈춘다

- **429 또는 403 이 한 번이라도** 나오면
- 응답 시간이 평소의 **3배**를 넘기 시작하면
- **CAPTCHA · 사람 확인 화면**이 뜨면 → **절대 우회하지 않는다** (`CLAUDE.md` 3-A 5번)

멈춘 뒤에는 무엇이 나왔는지 그대로 적는다. 「일시적인 것 같다」로 넘기지 않는다.

## 4. 끝나고 하는 일

```bash
# 숫자 대조 — 로그가 아니라 DB 를 센다 (CLAUDE.md 3-A 6번)
pnpm --filter @sacloud/worker exec tsx src/dev/battlelogCheck.ts

# 이어지는 집계 (D-203 의 절차가 그대로 유효하다)
pnpm --filter @sacloud/worker nexon clan-number --confirm
pnpm --filter @sacloud/worker nexon position-build --labels <정답.json> --confirm
pnpm --filter @sacloud/worker nexon round-build --confirm
pnpm --filter @sacloud/worker nexon clan-round-build --confirm
```

> 원문이 늘면 **기본 힙으로 OOM 이 난다.** 적재에는 `NODE_OPTIONS=--max-old-space-size=8192`.
> 대량 적재 중 DB 가 죽으면 **D-216** 을 읽어라 — 원인은 공간이 아니라 WAL 파일 생성이었다.

**판정 기준은 「몇 건 받았나」가 아니라 「1티어 17명과 개인랭킹 30명이 각각 몇 경기를
확보했나」이다.** `battlelogCheck.ts` 의 마지막 줄이 그것이다 (D-218).

## 5. 알아 둘 것

- **경기당 1회 호출이면 된다.** 한 응답에 양 팀 10명이 다 온다 — `event_type=kill` 이
  상대 팀 사망을, `death` 가 우리 팀 사망을 담는다 (D-218 실측). 두 번 부르면 같은 것을
  두 번 받는 것이고, 그것은 원본에 쓸데없는 요청을 보내는 셈이다
- **1티어 17명 중 8명만 클랜을 찾았다.** 못 찾은 이름:
  `유닠 · [h].jerry · ㅇ7ㅇ · 멍청이젤 · KKW · 김장은 · 혜진젤 · starry · 견자히`
  → 1순위 표본이 그만큼 얇다. **지어내지 않는다** (`CLAUDE.md` 3장 7번)
- **`battlelogWorklist.ts` 는 출력 폴더를 매번 비운다.** 우선순위를 따로 돌리면
  앞의 것이 사라진다. 지금 폴더의 `index.json` 은 1·2순위를 **손으로 합쳐 둔 것**이다
- 수집은 **멱등**이다. 중간에 죽어도 이어서 돌리면 된다 (`CLAUDE.md` 3-A 4번)
- POST 가 막히면 스니펫이 **자동으로 download 로 떨어지고 그 사실을 로그에 남긴다**.
  다운로드로 떨어지면 크롬 자동 다운로드 한도(약 66개)에 걸린다 — **그때는 멈추고
  dev 서버부터 확인해라** (D-203)
