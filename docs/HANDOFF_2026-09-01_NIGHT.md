- B어택 성공 = 블루팀 **비포지·리베포지·이층포지** 중 **2명 이상**이 먼저 죽음

코드는 구역 기반이라 **처음부터 다른 것을 재고 있었다.** 포지션 판정 정확도가 걸려 사용자가 뺐다.
**코드는 지우지 않았다** (CLAUDE.md 10-4). 되살리려면 포지션 판정부터 봐야 한다.

분모 실측이 이 결정을 뒷받침한다 — ⑤⑥ 은 경기당 분모 중앙값 **2**, 분모=1 인 행 **32.5%**,
분모≤5 가 **100%**. **경기 한 건으로는 원래 못 재는 축이었다.**


이것은 **모든 담당에게 해당한다.** 알 스위치뿐 아니라 어떤 상수·플래그도 마찬가지다.

#### ★규칙★ — 「없음」을 성공으로 읽지 마라 (폴링의 함정)

배포를 기다리며 운영 HTML 에 특정 문구가 사라졌는지 폴링했는데, **오탐이 났다.**

```bash
body=$(curl -s --max-time 25 "$URL")
if echo "$body" | grep -q "알이 깨지면"; then  아직 옛 빌드
else                                          ★배포됨★      ← 여기가 틀렸다
```

`curl` 이 실패하면 `body` 가 **빈 문자열**이 된다. 빈 문자열에는 찾는 문구가 당연히 없으니
**「사라졌다 = 배포됐다」로 빠진다.** 이 PC 는 `KingsNet.sys` 가 소켓을 깨서 요청이
수시로 실패하므로, 이 함정은 시간문제였고 실제로 13회차에서 밟았다.
그 오탐 때문에 「부분 배포인가 · 오염인가」로 한참을 헤맸다.

```
지켜라  ① HTTP 상태와 본문 길이를 **먼저** 확인한다
        ② 그 둘이 정상일 때만 문구 유무를 따진다
        ③ 실패는 «판정 불가» 로 따로 센다 — 성공도 실패도 아니다
```

**「기대하던 것이 안 보인다」와 「아무것도 못 받았다」는 다르다.**
전자만 판정 근거가 된다. 폴링·헬스체크·검증 스크립트 전부에 해당한다.
