## 3. 일이 어떻게 나뉘어 있나 (조직도 짤 때 쓸 구획)

프로젝트는 성격이 다른 **다섯 덩어리**다. 서로 의존 관계가 있다.

```
① 데이터 수집   ← 지금 최대 병목. 아래 넷이 전부 여기에 얹혀 있다
      │
      ├─▶ ② 계산      래더 · 랭킹 · 시즌 · 육각형 지표
      │        │
      │        └─▶ ③ 화면    기록실 · 랭킹 · 경기상세 · 홈 · 게시판
      │
      ├─▶ ④ 운영      배포 · 백업 · 마이그레이션 · 모니터링
      └─▶ ⑤ 신뢰      인증(칭호/마스터) · 권한 · 관리자
```

| 구획 | 무엇 | 지금 상태 | 위험 |
|---|---|---|---|
| **① 수집** | 3rd.supply 미러 · 넥슨 API · 병영수첩 | 미러만 자동. 나머지는 사람 손 | ★최상★ |
| **② 계산** | 래더 공식(D-145) · 시즌 창 · 지표 | 규칙 확정. 매시간 자동 반영 | 중 |
| **③ 화면** | Next.js 화면 전부 | 개편 진행 중 (오늘 큰 폭 변경) | 중 |
| **④ 운영** | Vercel 배포 · Supabase DB · 백업 | 동작하나 **이 PC 환경이 불안** | 상 |
| **⑤ 신뢰** | 소유권 인증 · 관리자 | DB 는 올라감. **동작 확인 안 됨** | 중 |

## 4. ★1순위 문제 — 수집이 사람 손을 탄다★

### 4-1. 무슨 일인가

기록의 원천이 셋인데 **둘이 막혀 있다.**

| 원천 | 무엇을 주나 | 상태 |
|---|---|---|
| 3rd.supply 미러 | SPL·10mountain 의 경기+라인업 | ✅ 자동. 20~30분 지연 |
| 넥슨 Open API | 개인 전적 | ❌ **클랜전 엔드포인트가 아예 없다.** 게다가 8/24부터 429 |
| **병영수첩** | IPL 의 경기+라인업+킬데스 | ⚠ **오늘 길이 뚫렸다** |

사장님은 3rd.supply 에서 가져오는 것을 그만두길 원한다
(*"서플라이꺼 가져오지 말라고 몇번 말해야돼"*). 그런데 **지금 그게 유일한 자동 공급원**이라,
대체 경로가 실제로 돌기 전에는 끌 수 없다. 이 순서는 사장님도 동의했다.

### 4-2. 오늘 밝혀진 것 (이게 판을 바꾼다)

```
서버에서 병영수첩을 부르면        403   ← 첫 페이지조차 못 연다. 오늘 재측정
진짜 브라우저에서 부르면          200   ← 보안 검사조차 안 뜬다. 오늘 처음 확인
```

앞 세션들은 「헤드리스도 막힌다」에서 멈춰 있었다. **헤드리스만 막힌 것이었다.**
실제로 배틀로그 한 건을 받아 확인했다 — 63KB, **탈주자 포함 양 팀 10명의 킬·데스·좌표**가
응답 하나에 다 들어 있다.

### 4-3. 그래서 정한 것

사장님 판단:
> *"게임 기록 사이트인데 사이트 주인이 컴퓨터로 항상 크롬을 켜놔야 기록이 되는 병신 사이트가 있어?"*

맞는 말이다. **작은 서버(VPS)에 진짜 크롬을 상주**시키기로 정했다.

```
채택   ① VPS 에 크롬 상주 → 15분마다 수집해서 창구로 전송
병행   ② 넥슨에 제휴 문의 (정식 접근을 받으면 브라우저가 필요 없어진다)
임시   ③ 사장님 PC 백그라운드 (PC 가 꺼지면 밀린다)
```

**준비는 끝났다.** 받는 창구를 오늘 운영에 열었다
(`POST https://3rdcloud.my/api/ingest/barracks`, 토큰 인증, 멱등).
지금과 나중이 **같은 창구**를 쓴다.

### 4-4. 남은 기술 장애물 하나

경기 목록 API 가 **한 번에 20건만** 준다. 페이지 넘기는 법을 아직 못 찾았다
(`page` `page_no` `offset` `start` `last_match_key` `match_key` 전부 실패).
**이걸 못 풀면 전수 수집이 불가능하다.** 다음 세션의 첫 일이다.

### 4-5. 비용·일정 감각

```
VPS            월 5~10 달러 (리눅스 1대 · 크롬 상주)
초기 전수 수집  IPL 23,100경기 × 1회 호출 → 원본에 무리 안 가는 간격으로 1.5~2시간
이후 유지      15분마다 신규분만 → 호출량 미미
```

| # | 위험 | 지금 상태 | 터지면 |

| 5 | **여러 세션이 한 저장소를 동시에 고침** | 오늘 빌드를 3번 깼다 | main 이 깨진 채로 배포된다 |

| 7 | **넥슨 API 차단(429)** | 8/24부터. 성공 폴링 0회 | 무기·상세 전적을 못 채운다 |
| 8 | 운영 DB 통로가 1개 | `connection_limit=1` | 동시 질의가 타임아웃. 화면이 500 |

### 위험 3 — 개발 환경 (매니저가 알아야 할 실무 제약)

이 PC 는 문서보안 프로그램이 소켓을 막는다.

```
로컬 서버가 어떤 포트로도 안 뜬다   → 화면을 로컬에서 못 본다. 배포해서 확인한다
Vercel 업로드가 끊긴다              → API 로 GitHub 소스를 빌드시켜 우회한다
DB 접속도 가끔 끊긴다              → 재시도를 감싸야 한다
```

**이것 때문에 작업 한 건당 시간이 2~3배 든다.** 개발 장비를 따로 두는 것이 장기적으로 싸다.

| **마이그레이션** | 밀려 있던 운영 마이그레이션 3개 적용 (클랜 마스터 인증 · 칭호 인증 · 아이디 가입) |
| **디자인** | 색을 3톤(op.gg 톤)으로 교체. 진홍 제거. 대비를 재고 골랐다 |
| **화면 개편** | 선수 카드 → 주간 그래프 + 정보줄 / 클랜 카드 동일 / 경기카드 승패 색 |
| **★수집★** | 병영수첩이 브라우저에서 열리는 것을 확인하고 **운영 수집 창구를 개설** |
| **사고 수습** | 내 커밋이 main 빌드를 깬 것 3건을 찾아 고침 (아래) |

### 오늘 배운 것 — 프로세스 개선 제안

**main 빌드를 3번 깼다.** 원인은 하나다: 여러 세션이 같은 파일(`packages/ui/src/index.ts`)을
동시에 고치는데, 내보내기 줄만 커밋되고 그 파일은 안 커밋됐다.
로컬에서는 파일이 다 있으니 `tsc` 도 테스트도 통과한다.

> **제안: 커밋 전 「깨끗한 worktree 빌드」를 규칙으로 만든다.**
> ```bash
> git worktree add --detach <임시> HEAD && cd <임시>
> pnpm install --frozen-lockfile && pnpm --filter @sacloud/web build
> ```
> 이것만이 세 종류(없는 파일 / 잠금파일 / 타입)를 전부 잡는다.

> **제안: 세션 간 파일 소유 구획을 정한다.**
> 지금은 두 세션이 같은 파일을 동시에 고치고 있다. `docs/TASK_LEDGER.md` 4장에
> 「파일 담당 구획」 절이 이미 있는데 지켜지지 않고 있다.
