## 0. 조사 범위와 전제

### 새 공식을 만들지 않았다

`POST_V1_REQUIREMENTS.md` 3장이 못 박은 대로 **3rd.supply 공식을 재현**하는 것이 목표다.
그래서 후보는 "더 좋은 공식"이 아니라, **스펙 §3이 `[미확인]`으로 남긴 해석 차이**다.

### 실제 경기 데이터를 쓰지 못했다 — 이유

| 후보 데이터 | 왜 못 썼는가 |
|---|---|
| 재구성된 넥슨 경기 | **0건.** 로스터가 비어 있어 아직 한 건도 재구성되지 않았다 (Phase 8.2) |
| mock 시드 3,000경기 | 래더 값까지 가짜다 (`formulaVersion="mock-fixture"`). 공식 비교의 입력이 될 수 없다 |
| 3rd.supply historical | WAF로 blocked. 수집하지 않았다 |

→ **숨은 실력값을 가진 합성 모집단**으로 시뮬레이션했다. 난수는 seed 고정이라 결과가 재현된다.
"래더가 그 숨은 실력을 얼마나 맞히는가"로 후보를 비교한다.

## 1. 먼저 확인된 것 — 공식 구조는 관측과 맞는다

스펙 §1·§2의 구조를 그대로 계산하면 §8의 관측 앵커가 **전부 재현된다.**

```
E  = 1 / (1 + 10^((Ro - R) / 3400))
패배 = -(K_lose × E)                   div1 K=24 · div2 K=30
승리 = round( round(Kw(R) × (1-E)) × winMultiplier )   Kw(R) = 36.6 - R/200
```

| 관측 (스펙 §8) | 계산값 | |
|---|---|---|
| div1 동급 패배 ≈ -12 | **-12** | ✅ |
| div2 동급 패배 ≈ -15 | **-15** | ✅ |
| div1이 div2에게 패배 ≈ -7 | **-7** | ✅ |
| div1 승리에 +11 · +19 없음 | **없음** | ✅ 2단계 반올림 때문이다 |

`+11`이 나오지 않는 이유: `round(9×1.15)=10`, `round(10×1.15)=12`. 11이 건너뛰어진다.
`+19`도 같다: `round(16×1.15)=18`, `round(17×1.15)=20`.

> **이 반올림 구조가 관측과 맞는다는 것 자체가, 역추적된 파라미터가 대체로 옳다는 증거다.**

### ⚠️ 검증 가능한 예측 하나

`+11 / +19 없음`은 **div1에서만** 성립한다. div2는 승리 배수가 1.00이라
`round(Kw×(1-E))`가 그대로 나오므로 **+11도 +19도 나올 수 있다.**

→ 만약 실제 3rd.supply 데이터에서 **div2 승리에도 +11/+19가 전혀 없다면**,
현재 파라미터 표(div2 배수 1.00)가 틀린 것이다. 실표본을 얻으면 가장 먼저 확인할 항목.

## 2. 개인 래더 후보 — 갈리는 것은 `0.6`의 적용 위치뿐

스펙 §3: *"0.6의 정확한 내부 적용 위치 (K에 곱하는지, 최종 증감에 곱하는지, 양쪽 모두인지)"*

| 후보 | 해석 | div1이 div2에게 패배 | 판정 |
|---|---|---|---|
| **P-A** | 반올림 **전**에 K·배수에 곱한다 | **-7** | 관측 재현 ✅ |
| **P-B** | 동급과 똑같이 계산한 뒤 **최종 증감**에만 곱한다 | **-7** | 관측 재현 ✅ |
| **P-C** | 양쪽 모두에 곱한다 (실효 0.36) | **-4** | ❌ **탈락** |

### P-A와 P-B는 앵커로 구분되지 않는다

패배 앵커(-12 / -15 / -7 / -15)가 **네 개 모두 같다.**
차이는 **교차 division 승리**에서만 나온다.

```
전 구간 대조 14,641건 중 다른 값 2,202건 (15.0%) · 최대 차이 1점
예: 본인 1000 vs 상대평균 1325 → P-A +12 · P-B +13
```

→ **실제 표본 20건만 있어도 96% 확률로 갈린다** (1 − 0.85²⁰).
지금은 표본이 없으므로 **어느 쪽도 확정하지 않는다.**

| | P-A | P-B |
|---|---|---|
| 스펙 표의 문자 그대로 (`24 × 0.6`, `1.15 × 0.6`) | **일치** | 표기와 어긋남 |
| 구현 단순함 | 같음 | 같음 |
| 시뮬레이션 분포 (평균/표준편차/실력상관) | 1598 / 524 / 0.883 | 1598 / 523 / 0.884 |

**차이가 실질적으로 없다.** 스펙 표기와 맞는 **P-A를 기본값으로 두되**, 실표본이 생기면 재확인한다.

## 3. 클랜 래더 후보 — 여기는 역추적 결과가 없다

`IMPLEMENTATION_PLAN_1.md` Phase 9 §4가 "클랜 래더와 개인 래더의 **결합 방식**"을 `[미확인]`으로 남겼다.
관측된 사실은 **분포 폭**뿐이다: 클랜 1위 1,840 · 20위 987 (개인은 1위 3,432).

| 후보 | 정의 | 시뮬레이션 분포 | 라인업 조작 | 이적 즉시 반영 |
|---|---|---|---|---|
| **C-1 team-elo** | 클랜을 하나의 개체로 보고 클랜 래더끼리 Elo | 평균 1645 · σ727 · 246~3013 | **불가** ✅ | 안 됨 |
| **C-2 member-mean** | 그 경기 선수들의 개인 증감 평균 | 평균 1664 · σ850 · 36~3307 | **가능** ❌ | 안 됨 |
| **C-3 roster-strength** | 등록 선수 상위 5명 개인 래더 평균 (배치 산출) | 평균 1635 · σ518 · 646~2616 | 불가 ✅ | **즉시** ✅ |

### C-2는 명확히 위험하다

```
같은 상대(1600)를 이겼을 때 클랜이 얻는 점수
  약한 5명(1200~1400) 출전 → +19
  강한 5명(2000~2400) 출전 → +12
```

**이길 수 있는 최소 전력을 내보내는 것이 클랜 점수에 유리하다.** 리그의 경기 질이 떨어진다.

### C-3은 래더가 아니다

이적·라인업 변화가 즉시 드러나는 것은 장점이지만(에이스 이탈 시 1940 → 1800),
**경기 결과가 점수에 들어가지 않는다.** "약팀을 이겨서 오른 점수"라는 개념이 없어
`승리 | 패배 | 승률 | 래더`를 함께 보여 주는 원본 랭킹 화면과 맞지 않는다.

→ **C-1 권장, C-3은 보조 지표(클랜 전력 표시)로 병행.** 단 아래 단서가 있다.

### ⚠️ 어느 후보도 관측된 분포 폭을 재현하지 못한다

관측 클랜 래더는 987~1,840(폭 약 850)으로 **개인 래더보다 훨씬 좁다.**
개인 래더 상수(D=3400, K 24/30)를 그대로 쓰면 세 후보 모두 폭이 2~3배 넓게 나온다.

→ **클랜 래더는 개인과 다른 상수를 쓴다고 보는 것이 맞다.**
`RatingConfig`에 `divisionKey`가 이미 있으므로 `"clan"` 설정을 따로 두면 된다.
정확한 상수는 **`[미확인]`이며, 실표본 없이 추정하지 않았다.**

## 4. 악용 가능성 — 발견된 구멍

### 4-1. ⚠️ 양학이 막히지 않는다 (가장 큰 구멍)

```
1,000점 상대만 300경기 이김 → 1800 → 3555
마지막 10경기에서도 여전히 +3.0/경기 · 증감 0에 도달하지 못함
```

원인은 **D = 3400**이다. 일반 Elo(400)라면 800점 차에서 기대승률이 0.99를 넘어 증감이 0으로 죽는다.
D가 3400이면 800점 차에서도 기대승률이 0.63 수준이라 **계속 점수가 붙는다.**

### 4-2. ⚠️ 승률 왜곡이 통한다

```
약체(1100)만 골라 300경기, 승률 86% → 2874
강자(2500)와 300경기, 승률 55%   → 2679
```

**약체만 고른 쪽이 더 높다.** 래더가 "누가 강한가"가 아니라 "누구와 붙었는가"를 반영한다.

### 4-3. ⚠️ div1은 제로섬이 아니다 — 활동만 해도 오른다

```
동급 div1 경기: 승 +17 / 패 -12  → 한 경기당 +5가 시스템에 주입된다
승률 50%로 200경기 → +158점
쉬는 사람 → 0점 (감쇠 규칙이 스펙에 없다)
```

div2는 승 +15 / 패 -15로 **정확히 제로섬**이다. div1만 인플레이션이 있다.
시뮬레이션 4,000경기에서 총합 **+31,465점**이 늘었다.

이것이 "버그"인지 "1부리그 우대라는 원래 설계"인지는 **관측으로 판정할 수 없다.**
다만 결과적으로 **랭킹이 실력보다 경기 수에 끌린다.**

### 4-4. 정상 동작으로 확인된 것

| 케이스 | 결과 |
|---|---|
| 업셋 | 약자 승 +25 > 강자 승 +8 / 강자 패 -17 > 약자 패 -7 ✅ |
| 이겨서 잃거나 져서 얻는 구간 | 전 구간에서 **없음** ✅ |
| 반복 대전 (같은 실력 500경기) | 점수 차가 발산하지 않음 (최대 455, 무작위 진동) ✅ |
| 신규 유저 | 배치 10경기 후 78경기만에 상위권 도달 ✅ |
| 장기 미접속 | 점수 변화 0 (감쇠 없음) — 정책 판단 필요 |
| 배치고사 | 증감 0 ✅ |

## 5. 권장안 (승인 대상)

| 항목 | 권장 | 근거 |
|---|---|---|
| 개인 래더 공식 | 스펙 §1 구조 그대로 | 관측 앵커 4개 전부 재현 |
| `0.6` 적용 위치 | **P-A**(반올림 전) 잠정 | 스펙 표기와 일치. **실표본 확보 시 재확인** |
| 클랜 래더 | **C-1 team-elo** | 라인업 조작 불가. C-2는 조작에 직접 노출 |
| 클랜 상수 | 개인과 **분리**된 `RatingConfig` | 관측 분포 폭이 개인과 다르다 |
| 클랜 전력 표시 | C-3를 **보조 지표**로 병행 | 이적·로스터 변화가 즉시 보인다 |
| 래더 반영 대상 | **완전히 재구성된 경기만** | D-056. incomplete match는 계산에 넣지 않는다 |

### 양학·인플레이션 대응은 **제품 정책**이라 결정하지 않았다

원본에 없는 규칙을 우리가 추가하는 것이므로 임의로 넣지 않았다. 선택지만 적는다.

1. **아무것도 하지 않는다** — 원본 재현 최우선. 양학과 인플레이션도 원본의 성질로 본다
2. **래더 차 상한** — 예: 상대와 800점 이상 차이나면 승리 증감 0 (양학 차단, 원본에 없음)
3. **동일 상대 반복 감쇠** — 같은 상대와 N회 초과 시 증감 축소 (반복 대전 차단, 원본에 없음)
4. **시즌 소프트 리셋** — 인플레이션을 시즌 경계에서 흡수 (스펙 §3에서 이미 `[미확인]`)
5. **경기 자격 필터 강화** — 리그 등록 클랜 간 경기만 래더 반영 (이미 D-056으로 부분 적용)
