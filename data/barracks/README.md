# data/barracks — 병영수첩 BattleLog 파생 자료

사양은 `docs/PLAYER_TRAITS_SPEC.md` 다. 여기 있는 것은 **그 사양이 쓰는 입력 자료**다.

수집은 사용자의 로그인된 브라우저가 한다 (서버에서 부르면 403 · `CLAUDE.md` 3-A 5번).
스니펫은 `packages/db/legacy/barracks-battlelog-snippet.js` · `barracks-sniff-snippet.js`.

| 파일 | 무엇인가 |
|---|---|
| `zonemap.json` | **구역 지도.** 10 단위 격자 셀 → `2F`(2층) · `B` · `SHORT`(숏/A). 357칸 |
| `sniper-lane.json` | **스나싸움 구역.** 뱃지 전용이라 위 세 구역과 겹쳐도 된다 |
| `zones-raw-pixels.json` | 구역 지도를 만든 **원본 픽셀**. 노랑=B · 보라=2층 · 하늘=숏 |
| `evidence-killmap.png` | 킬 좌표 산점도 (구역을 칠하기 전에 본 그림) |
| `evidence-zonecheck.png` | 칠한 구역을 좌표 위에 겹쳐 본 검증 그림 |
| `weapon-beta-20260823.json` | 무기(라플/스나) 판정 베타 수집분 (D-114) |

## 구역 지도는 어떻게 나왔나

사용자가 킬 좌표 산점도 위에 **형광펜으로 직접 칠해 준 이미지**에서 픽셀을 뽑았다.
그 픽셀이 `zones-raw-pixels.json` 이고, 10 단위 격자로 접은 것이 `zonemap.json` 이다.

겹치는 칸의 우선순위는 **2층 > B > 숏** 이다. 사용자가 2층·B 표시는 "완벽에 가깝다" 고 했고
숏만 다시 칠했기 때문이다 (`docs/PLAYER_TRAITS_SPEC.md` 2절).

> ⚠ **2층은 A 의 위층이라 미니맵 x/y 가 겹친다.** 좌표만으로 2층과 숏을 가를 수 없다.
> 그래서 "최다 구역" 으로 포지션을 정하지 않고 **분포 전체를 학습**한다.

## 왜 저장소에 넣었나

2026-08-29 이전에는 이 파일들이 **작업용 임시 폴더에만** 있었다.
세션이 정리되면 사라지고, 그러면 사용자가 구역을 다시 칠해야 한다.
파생물이지만 **사람 손이 들어간 입력**이라 저장소에 둔다.
